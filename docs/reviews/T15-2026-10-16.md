## 4. 做法,以及為什麼

紅測試範例(`card-static-samples-test-support.ts` 的 GOOD_* ,只讀、沒改)已經把卡片寫成 `<HudPanel title=… controls={createWindowControls()} fill>`。prop 名字跟範例對齊,掃描不查這個名字,只看畫出來的矩形。`fill` 在 `HudPanel` 加上 class `hud-fill`(不是 `hud-frameless` / `hud-solid`,卡片原始碼的 class 掃描抓不到 `--hud-solid` 這種變數,也不該抓到這個 class)。

面板撐滿不用 `100vw`(有捲軸時會比視窗寬)。`position: fixed; inset: 0`,`.hud-cut` / `.hud-cut-inner` 用 flex 把高度傳下去,捲動只放在 `.hud-body`(`overflow: auto`)。`html:has(.hud-fill)` 把整頁 `overflow: hidden`,避免文件自己長出捲軸把視窗擠窄。標題列(有 `hud-frameless` 時)是捲動區的兄弟,不跟著捲;這張測試不開無框,所以現在看不到標題列,跟工單「還不會變的」一致。

第一次量教學卡,底邊墨水是 1.85,不是 1。原因:內容比視窗長時,捲動區自己的 `padding-bottom` 會跟著內容捲走,字貼到視窗下緣,往內 7 像素的量尺把字也算成墨水。考試卡第一題短,底邊是空的,所以那張過了。修法是在捲動區外面(`.hud-cut-inner`)留 8px 底距,這圈不捲,下緣只剩 1 像素黑線。左右邊距仍靠 `.hud-body` 既有的 `0.95rem` 內距(約 15px,≥ 12)。

`HudField` 照 `HudButton` 的畫法:外層黑底、1 像素 padding、切左上與右下(8px);內層 `.hud-field-face` 墊 `--hud-panel`,clip 縮 1 像素。輸入框自己 `border: none`、`background: transparent`、字型與字色用 `--hud-font-body` / `--hud-text`、寬度 100%。`:focus-within` 把外層底色改成 `--hud-accent`(橘色只在線上,不印字),並加一圈 `outline`(外擴 6 像素的像素差才穩)。停用用 `:has(:disabled) { opacity: 0.45 }`,跟按鈕一樣變淡;opacity 不放進 transition,因為停用的量尺只等兩幀。

`--hud-pass` / `--hud-fail` 用工單算過的 `#146c2e`、`#b31d28`(對面板最差對比約 5.21 / 5.36,門檻 4.5)。結果那一行的字是標記裡的「✓ 答對了」「× 答錯了」(U+2713、U+00D7,符號後一個半形空格),`data-result` 用運算式選 `pass` / `fail`。評分失敗那行不加符號、不帶 `data-result`。

送出鍵跟鍵盤走同一個 `submitFill` / `submitApply`,`disabled={view.submitting}`。出現時機照工單:`!(view.result && !view.error)`(看到結果就收掉,評分失敗還在)。沒有加 07 的「換類別」「深入這個」(Q1:不為了湊三顆加空按鈕)。

展示頁:頁首包進 `data-gallery="head"`,底色 `var(--hud-solid)`,不用第二個 HudPanel(T14 的量尺找第一個面板)。深色背景的開關留在頁首裡。HP 條三組橫排、兩個作答欄並排(各包一層 div,欄位寬度才等於容器寬)、頁首與頁面 padding 縮小。基底面板下緣在 y≈849,視窗 900,測試要求 ≤ 896;橫排省下來的高度蓋過頁首 padding 與作答欄。

卡片 `<style>` 不畫框(拿掉 `.badge` 的 `border-radius`)。`.lc-example` 只留 `border-left`,顏色改 `var(--hud-line)` / `var(--hud-solid)`。徽章底色 `--hud-accent-wash`、字 `--hud-text`(橘色不印內文)。沒有 `style=` 屬性、沒有 inline `<style>`、沒有外部網址。考試卡沒有 import `@learning/ui-shared` 的根。
