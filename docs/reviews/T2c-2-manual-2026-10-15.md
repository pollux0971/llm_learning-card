## (2) lc-start 頁的 CSP(驗收 11;派令第 2 點)

lc-start 的回應(Network,reload 一次量到):`200`,`Content-Type: text/html; charset=utf-8`、`X-Content-Type-Options: nosniff`、
`Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`。Tauri 沒有把 `tauri.conf.json` 的 CSP 疊上去,也沒有換掉。

- **有沒有擋到自己:沒有。** 四種失敗、五次啟動,載入時 console 都是 **0 則**。頁內 `<style>` 有生效:`body` 是 `sans-serif`、
  margin `24px`;`pre` 是 `pre-wrap`、`monospace`、`user-select: text`。頁面沒有 `<script>`(`document.scripts.length` 是 0)。
- 該擋的都有擋。探針在頁面的計時器裡跑,因為檢查器的 `Runtime.evaluate` 本身不受 CSP 限制。console 原文:

  ```text
  Refused to execute a script because its hash, its nonce, or 'unsafe-inline' appears in neither the script-src directive nor the default-src directive of the Content Security Policy.
  Refused to load lc://localhost/cards/x.png because it appears in neither the img-src directive nor the default-src directive of the Content Security Policy.
  Refused to connect to ipc://localhost/x because it appears in neither the connect-src directive nor the default-src directive of the Content Security Policy.
  ```

  `new Function` 丟出:`EvalError: Refused to evaluate a string as JavaScript because 'unsafe-eval' or 'trusted-types-eval' is not an allowed source of script in the following Content Security Policy directive: "default-src 'none'".`
  `securitypolicyviolation` 發生 4 次(script-src 的 eval、script-src-elem 的 inline、img-src、connect-src),`originalPolicy` 都是上面那一行。
  動態插入的 `<style>` 有生效(`style-src 'unsafe-inline'` 本來就允許)。
- 附帶一提:Tauri 的 IPC 初始化腳本照樣被注入這一頁(`typeof window.__TAURI_INTERNALS__` 是 `object`)。
  但這一頁沒有任何 script 能執行,`connect-src` 是 `'none'`,`setup` 也不在 capability 的 `windows` 裡。記下來,不算發現。

ok 狀態的兩個視窗(build 產物,`tauri://localhost`)也看了:回應帶的是 Tauri 合成的 CSP(`tauri.conf.json` 那一份,`script-src` 多了兩個 `sha256-`)。

## 發現

### F1:「指標檔權限不夠」的畫面,給的兩個指令都跑不起來(驗收 6)

- 畫面把「權限不夠」寫成原因之一(`../../apps/desktop/src-tauri/src/start_screen.rs:69` 起)。
  但它給的 `vault.ts show` 與 `vault.ts init … --force`,剛好都卡在 `EACCES`:exit 1,沒有改任何東西,重開 app 還是同一個畫面。
- 人只照畫面做,出不去。要先自己 `chmod u+rw <指標檔>`,畫面沒有寫。
- `vault.ts` 遇到讀不到的舊指標就停下、不硬蓋過去,這是對的:讀不到就沒辦法照 ADR-050 先印出要丟掉的內容。
- 建議改畫面文字:在 pointer-unreadable 那一段加一行,大意是「如果是權限不夠,先執行 `chmod u+rw '<指標檔路徑>'`」。
  路徑用 `shell_word` 包起來(跟 marker-mismatch 同一套引號)。只動 `start_screen.rs` 的文字,不動 `vault.ts`,也不拆成兩個狀態。
- 另一條路是讓 `vault.ts init --force` 遇到 `EACCES` 時印「舊指標讀不到(權限)」再照樣覆寫。這會改 T5/T8 的行為,
  也違背「要讓人看見丟了什麼」,我不建議。

### F2:真的 app 在 `XDG_CONFIG_HOME` 底下寫了 window-state 外掛的檔

- `tauri-plugin-window-state` 2.4.1 在 `RunEvent::Exit` 時呼叫 `save_window_state`(`create_dir_all` 再 `std::fs::write`),
  位置是 Tauri 的 `app_config_dir`,也就是 `$XDG_CONFIG_HOME/dev.learningcards.desktop/.window-state.json`。
  外掛在 `../../apps/desktop/src-tauri/src/main.rs:71` 註冊。
- 五種狀態每次正常關閉都會寫。四種失敗狀態寫的是 `setup` 視窗的位置與大小。
- 驗收 5 的自動測試走 probe(`lc-fs`),不會啟動 Tauri,所以看不到這件事。這是 phase-1 就有的功能,不是 T2c-2 帶進來的。
- 驗收 5 的字面是「前後 `XDG_CONFIG_HOME` 目錄……的檔案清單與內容雜湊不變」,場景寫「wrote no file anywhere」。
  以真的 app 來說,這兩句都不成立;只對指標檔、標記、learning/ 成立。
- 兩條路(由技術顧問定):
  - A(我建議):把驗收 5 與場景的意思收窄成「不寫指標檔、標記與 learning/」。ok 狀態本來就要記住視窗位置(phase-1 的功能);
    失敗狀態寫一個視窗位置檔,無害。要改的是 `phase-2.feature` 的措辭,歸測試 agent 與統籌,不歸前端。
  - B:失敗狀態不掛 window-state 外掛。只把 `setup` 列進 denylist 不夠:`RunEvent::Exit` 照樣會寫一個 `{}` 的檔
    (這一點是讀外掛原始碼得到的,沒有實測)。

### F3(觀感,小):`word-break: break-all` 把字從中間切開

- `../../apps/desktop/src-tauri/src/start_screen.rs:130`。截圖裡 `--force` 被折成 `--f` 與 `orce`,`"learning_dir"` 被折成 `"learning` 與 `_dir"`,
  路徑也在任意字元處斷行。
- 複製出來沒問題(上面量過,是完整的一行),但人對著畫面手打時容易打錯。
- 建議改成 `overflow-wrap: anywhere`:只有一個字整個放不下時才斷,`--force` 這種短字不會被切開。
