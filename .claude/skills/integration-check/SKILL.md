# /integrate — 整合驗收

目標:`$ARGUMENTS`

整合點的驗收比 phase 嚴格,因為它的意思是「**系統現在是完整可用的**」(ADR-024)。

## 第一步:定位

從 `docs/01-roadmap.md` 找到該整合點的段落,取得:
- 「你做得到什麼」——這是驗收的真正標準
- 需要的 phase 清單
- 整合工作清單

讀 `docs/integration/<in>-*.feature`。

## 第二步:前置檢查

- roadmap 列的每個 phase 狀態都是 `done`。有未完成的,列出並停。
- **前一個整合點已通過**(I1 的前一個是 Wave 0 全部 done)。沒有就停——整合不能跳(ADR-024)。

## 第三步:重複清除檢查

這是整合最容易漏掉的一步。

掃描每個涉及的 `FEATURE.md` 的「Wave 0 的重複」表,找出「整合時移除於」等於這個整合點的項目。
對每一項:

- 用 Grep 確認該檔案 / 該類別**已經不存在**
- 還在 → 列出來,**不算整合完成**。留著 stub 的整合是假整合
- 已移除 → 在 `FEATURE.md` 的表上標記已移除與日期

## 第四步:自動場景

```
NODE_OPTIONS=--import=tsx npx cucumber-js --tags "@<in> and not @manual"
```

位置路徑(`docs/integration`)拿掉——`cucumber.js` 的 `paths` 與 CLI 位置路徑是合併不是覆蓋,
路徑本身不會縮小範圍,靠 `--tags` 才是真的在篩選(ADR-036/037)。`NODE_OPTIONS=--import=tsx`
前綴不可省,沒有它會 `ERR_UNKNOWN_FILE_EXTENSION` 直接掛掉。

分開回報三類:
- 一般場景:這個整合點的新能力
- `@regression`:前面的整合點有沒有被弄壞——**這類失敗最嚴重**
- `@llm`:需要真呼叫的,問使用者要不要跑(會花錢)

## 第五步:單獨執行全檢

**跑每一個** `FEATURE.md` 的「單獨執行」指令,不只這次整合涉及的。

ADR-022 要求整合後仍然要能單獨跑。這一步是耦合檢測器:
如果 03 的整合讓 04 的單獨執行壞掉,那代表有人偷偷加了依賴。

任何一個跑不起來 → 列出來,**不算整合完成**。

## 第六步:變異測試

對涉及的每個模組跑,確認整合後仍達門檻。

整合常見的退化:接上真模組後,原本測 stub 的測試變成測真東西,
邊界情境反而沒測到。分數掉下來就是這個原因。

## 第七步:端到端場景

列出 `@e2e` 場景,一字不改地呈現給使用者:

```
## 這是「完整可用」的標準,請親手確認

@e2e Scenario: A person completes a review session and the schedule advances
  Given 3 cards are due today
  When the person runs the review command
  …

roadmap 說 I2 之後你做得到:「每天在終端機複習,間隔重複真的在跑」

你做得到嗎?
```

**這一項不能由測試代替。** 使用者說做不到,就是沒整合完,不管測試結果如何。

**等回覆。**

## 第八步:其他 @manual

列出剩下的 `@manual` 場景成 checklist,問哪些沒過。**等回覆。**

## 第九步:判定

第三到第八步全過 → **整合完成**。

### 若完成

1. `docs/01-roadmap.md` 的「現況」表:目前階段改成下一個整合點
2. 該整合點的標題後加 `✓ <日期>`
3. 掃所有 `NEXT.md`,把整合 gate 是這個整合點的 phase,gate 打勾;若三類 gate 都滿足了,列出這些新解鎖的 phase
4. 建議 `git tag <IN>`
5. 回報:
   ```
   ✓ <IN> 整合完成
   - Phase:X / X done
   - 重複清除:X / X
   - 自動場景:X / X(regression X / X)
   - 單獨執行:X / X
   - 變異測試:各模組均達門檻
   - 端到端:使用者已確認
   - 新解鎖的 phase:…
   - 下一個整合點:…
   ```
6. 加一句:roadmap 的「通過後立刻做」寫了什麼(例如 I1 是「把真的素材餵進去」、
   I2 是「連續用一週再往下」)——**提醒使用者去做,那比繼續寫程式重要**

### 若未完成

不改任何狀態。逐項列出哪一步沒過。

## 禁止事項

- 不跳過整合點
- 不在 stub 未移除時標完成
- 不在任何「單獨執行」跑不起來時標完成
- 不在使用者說「做不到」時標完成,不管測試多綠
- 不修改整合的 `.feature` 讓它通過
