## 專項:改了 T19 既有測試的 2 列,是規格改了還是放寬
結論:是規格改了所以舊斷言跟著改,不是放寬。
- 舊 2 列:97 或 98 個字 + 一行「example 加一個空白」+ 內容 + 結束。舊規格把「example 後面有空白」當一般文字,所以算 97 加 example 1 字加內容 2 字 = 100 / 98 加 3 = 101(100 通過、101 不通過)。
- 新 2 列:100 或 101 個字 + 同樣的圍欄。照契約 §2 步驟 1(圍欄整段拿掉)加顧問裁決乙(example 後面只有空白或 Tab 就是 CommonMark 的開始行),整個圍欄不算字,剩 100 / 101,所以 100 通過、101 不通過。這個 100 通過 / 101 不通過的一對還在,邊界在同一個地方。
- 我手算:兩列期望值 100、101 是依「圍欄整段拿掉」算的,不是抄實作;反證:如果圍欄沒被認出(當一般文字),100 個字加 example 加內容會是 103,測試會紅。所以新斷言比舊的更能分辨有沒有認出圍欄。
- 「example 後面還有字」96 / 97 兩列沒動(96 加 example 1、js 1、內容 2 = 100;97 → 101),仍然不是圍欄;另一張「與 validateCard 一致」的核對表也沒動,只加一行註解。
- 沒有發現被放寬的地方。

## 期望值手算
新檔每條都是「前」「後」夾著一個圍欄,圍欄整段拿掉剩 2 字;examples 是圍欄內容(已 trim)。N=3 時內容是「內容 內容」,N≥4 時內容含內層三反引號的 js 圍欄,才分得出「數量比開始少的不結束」。A 的檔尾沒換行例子算 1 字(只剩「前」)。B 的兩個反引號例子:前、example、ab、後各 1 = 4,examples 0。全部對照 §2 與裁決乙,沒有照抄實作。
