## 做法與為什麼

摘要與清單放在新檔 `packages/core/src/ingest/siblings.ts`,生產路徑與 golden 登記表共用,不另寫一份。

`cardSummary` 先拿掉 example 圍欄(三個以上反引號加 `example` 開始、同數量結束),再把空白壓成一個半形空格,取到第一個句子結束(全形 `。！？`、半形 `!?`,或 `.` 後面接空白或結尾),超過 60 個 code point 就截到 60 再加 `…`。沒有 import `normalizeBody`:那個函式在 12,02 不開往 12 的邊(工單寫了不會繞成圈)。現有 `listCardIds`(01 與 11)只回全庫的 id、不含 body,也分不出「這一個分類」,所以 `loadCategoryCards` 自己掃 `cards/<category>/*.md`(排除 `.short.md`),解析用既有的 `parseCardText`,frontmatter 對不上契約或 YAML 壞掉就略過、不丟錯。

冒號用半形 `:`(U+003A)。工單散文寫「全形冒號」,但工單程式範例與紅測試釘死的字元都是 U+003A。跟著釘死的位元組走,不然測試必紅。

`generateChildren` 每次呼叫都 `loadCategoryCards` 再 `listSiblings`。`generateChildrenForCards` 的「處理完一個父卡立刻寫檔」順序沒改,所以第二個父卡看得到第一個剛寫的子卡。沒有 sibling 時 `formatAlreadyCovered` 回空陣列,header 與 T12 之後逐字相同。

golden 的三個資安輸入:sibling 來自固定檔(L0 用 `golden/ingest.cards/2026-10-15`,排在前面的子卡用 `fixtures/golden-t18`),id 由登記表自己配(`sec-0001` 起,父卡用 `sec-9000` 以免被排除),不寫進 prompt。行由 `listSiblings` 的輸出交給 `formatAlreadyCovered`。原三個輸入的 id 與拿掉區塊之後的 prompt 位元組不變(測試釘的 sha256)。泛化三個接在後面,`group: 'generalization'` 只加在這三個上,分類用 `chemistry`,parent_id 用 `chm-golden-<key>`,不沿用 `security` / `sec-golden-`。泛化不含前面切片的子卡。

`--overlap-siblings` 沿用 T12 的 `loadSide`、`overlapCoefficient`、`normalizeBody`、`charNgrams`。門檻 0.5 用 `>=`,觀察是 0.3 ≤ 重疊 < 門檻,不比自己的 key,A↔B 只算一次,兩邊都是子卡時 child 取 `key#index` 字典序較小的那張。`maxOverlap` 從所有比過的對取,不是從清單取。CLI 重疊值 `toFixed(3)`,成對那一行印兩邊的 key 與標題,觀察段一定印(0 對也印「觀察」),pairs 空則退出碼 0,否則 1。

`scripts/boundaries.allow.json` 加了工單指定的那一條 12 → 02,reason 照抄。新的兩個 `.ts` 落在既有目錄前綴(`packages/core/src/ingest/`、`packages/core/src/prompt-quality/`),`boundaries.owners.json` 不用另開行(同 T12 / T6 的取捨)。`npm run boundaries` 涵蓋 365 / 365,100%。
