## 做法與為什麼

編排只留在 `packages/core/src/session/engine.ts`。`openDay` / `pauseDay` / `unpauseDay` / `summarizeDay` / `snapshotAfterReview` 照 `scripts/review.ts` 原來的分支搬過去,包含「壞快取先記 warning 再重建、stale 不記 warning、暫停不建 session」。CLI 只留讀 stdin、印字、`--dry-run`,以及「暫停日不需要帳本」的那一次只讀預檢。預檢只讀不寫,所以暫停時印的字與退出碼跟原來一樣,而且查帳本之前就返回。snapshot 失敗的 hint 仍由 CLI 印到 stderr;側車的 summary 只帶 status,不帶 hint。

`submitAnswer` 加了可選的第三個參數,沒給時行為不變。陣列只用於填空,每個空格 trim 後原樣比對,不再用逗號切。應用題收到陣列在叫審核之前就丟錯。`keepOnError` 且 `pass === null` 時不設 `hadError`、不前進 `typeIndex`、不 shift、不寫 `reviews.json`、不加 `errors`,回 `cardDone: false`。

訊息形狀在 `protocol.ts`,只 import zod,用 `TextEncoder` 算位元組,不碰 `node:`。`classifyRequestLine` 先看大小(太大不讀 id),再看一行裡有沒有 CR(有就 `bad-request` 且 id 是 null,向量如此),再 JSON、v、method、其餘 schema。`v` 存在但不是 `1`(含字串 `"1"`)是 `unsupported-version`;method 是字串但不在五個裡是 `unknown-method`;讀不出整數 id(字串、0、負數、小數)就帶 null。

handler 不碰 stdio、不 `process.exit`。`routerFactory` 第一次非暫停的 `start` 才呼叫;丟錯不留 router、不留 session,下一次 `start` 再叫。暫停的 `start` 不叫 factory(暫停日不需要帳本)。`root-mismatch` / `router-unavailable` 由側車的 factory 丟 `ReviewStartError`,handler 只認 kind;其他例外是 `internal`,回應只用固定句子。`next` / `submit` 先看磁碟上的快取是不是暫停,所以中途把快取標成暫停會回 `paused` 而不是繼續用記憶體裡的 session。reteach 用 `findCardFile` 先找縮短版,找不到退回原卡,路徑轉成相對 learning 根的正斜線,不送內文。填空 `pass === false`(含 stage 2 的 partial)才帶 `correctAnswers`。`review-record-changed` 丟掉記憶體裡的 session。

側車第一個 import 是 `review-sidecar-stdio.ts`,把 `console.log` / `info` / `debug` / `warn` 導到 stderr,`_env` 排第二。stdout 只用 `process.stdout.write` 寫協定行。錯誤的 stderr 用 `writeSync` 寫在 stdout 之前:pipe 上的 stderr 會緩衝,測試在行程還活著時讀不到非同步寫入。分行只用 `\n`,U+2028 / U+2029 與 `\r` 留在同一行。stdin EOF 自然結束,退出碼 0。`LC_REVIEW_TODAY` 不合 `YYYY-MM-DD`(含空字串)印 `[review-sidecar] bad-today`、退出碼 2、不印 hello。

Rust 不改簽名。`request_line` 只查 v、id、method 是不是字串、params 是不是物件、長度;通過就 `serde_json::to_string` 原樣回。`parse_response_line` 只查是不是物件、v 是不是 1、長度。子行程 `env_clear` 之後只帶 `spec.env`。`SidecarHost::call` 用 `try_lock`,鎖不到立刻回 `busy`。識別碼沒有比上一個送出的大就不送。非協定行丟掉並 `eprintln` 固定的一行;超過 256 KiB 的那一行回 `bad-response`。逾時、沒有 hello、側車結束都 kill 再 wait。`main.rs` 的 `.setup` 仍是直接呼叫 `open_windows`(T21 的接線檢查不允許中間有別的括號),所以 `SidecarHost` 在 builder 上 `.manage`,learning 根用啟動時那一份 `LearningRoot` 的複本,不是另讀指標檔。`commands.rs` 的 `review` 本體只有 `host.call`,不看內容。`lib.rs` 已經有 `pub mod review_sidecar`(紅測試作者放的),沒有再改。

webview client 只 import `protocol.ts` 與 `@tauri-apps/api/core`。給了 `handler` 就走程序內,否則 `invoke('review', { request })`。id 在 await 之前加一,失敗也算。`boundaries.allow.json` 加一條 10-desktop-shell → 11-review-cli,理由寫 ADR-075。`review-sidecar-stdio.js` 也登記進 owners:boundaries 解析 import 時保留 `.js`,只登記 `.ts` 會被當成沒有落點。
