## 1. `register_uri_scheme_protocol` 能不能掛我們的檢查

**能。** 這就是實作方式。

簽章(tauri 2.11.5 `Builder`):

```text
register_uri_scheme_protocol(uri_scheme, handler)
handler: Fn(UriSchemeContext, http::Request<Vec<u8>>) -> http::Response<T>
```

handler 拿到的是完整的 HTTP request,不是已經過白名單的路徑。內建 `asset` handler(`protocol/asset.rs`)自己做的就是:對 `request.uri().path()` 去掉開頭的 `/`,用 `percent_encoding::percent_decode` **解一次**,然後才 `scope.is_allowed`,通過才 `File::open`。我們可以掛同一個形狀,只是把 glob scope 換成 §13 的白名單:

1. 從 request URI 取出 path;
2. `percent_decode` **恰好一次**(不迴圈解到不變);
3. 把解完的字串交給跟 read command 同一份白名單;
4. 通過才把它接到 `learning/` 根目錄去讀;不通過就 403,只 `log::error`,不寫 §10。

Linux 上自訂協定的 URL 形式,文件寫的是 `<scheme>://localhost/<path>`(Windows / Android 才是 `http://<scheme>.localhost/<path>`)。本張只做 Linux。

協定名稱不用 `asset`。內建註冊在 `manager/webview.rs` 是:

```text
#[cfg(feature = "protocol-asset")]
if !registered_scheme_protocols.contains("asset") { 註冊內建 handler }
```

若我們自己先註冊名為 `asset` 的 scheme,feature 有開時內建會被跳過。那是「換成我們的 handler」,不是「關掉」。驗收要的是關掉(或 scope 空)再加上「直接用 `asset:` URL 讀 `learning/` 會被拒」。所以:

- 自訂協定用別的名字(`lc`),掛上面那四步;
- 另外註冊一個名為 `asset` 的 handler,**一律拒絕、不讀檔**。這樣即使以後有人打開 `protocol-asset`,`contains("asset")` 為真,內建 handler 不會掛上;直接打 `asset:` 也進我們的拒絕函式。

## 2. 內建 `asset:` 能不能關

**能,而且現在就是關的。可靠的開關是 Cargo feature,不是 `enable` 欄位。**

| 層 | 現況 | 依據 |
|---|---|---|
| Cargo feature `protocol-asset` | **沒開** | `tauri` 2.11.5 的 `default` features 是 `wry`、`compression`、`common-controls-v6`、`dynamic-acl`、`x11`、`dbus`。`protocol-asset` 不在裡面。本 repo `Cargo.toml` 是 `tauri = { version = "2", features = [] }`,空陣列仍會開 default,但不會開 `protocol-asset`。`protocol/mod.rs` 的 `pub mod asset` 與 `webview.rs` 的註冊都在 `#[cfg(feature = "protocol-asset")]` 後面,沒開就連編譯都不會進去。 |
| `tauri.conf.json` 的 `assetProtocol` | **沒寫** | `security` 只有 `"csp": null`。 |
| 沒寫時的預設 | `enable: false`,`scope: []` | `AssetProtocolConfig` 兩個欄位都 `#[serde(default)]`,`bool` 預設 false,`FsScope` 預設空。官方 Security 預設區塊就是這兩個值。 |

**`enable: false` 單獨不夠。** 我讀過的註冊點(`manager/webview.rs`)在 feature 有開時**不看** `config.asset_protocol.enable`,只要 scheme 名單裡還沒有 `asset` 就註冊內建 handler。`enable` 只出現在設定結構,沒有接到那個 `if`。所以「關掉」的做法是:

1. 不開 `protocol-asset`(現在已經沒開,實作維持不開);
2. `tauri.conf.json` 明寫 `"assetProtocol": { "enable": false, "scope": [] }`,讓「關」與「scope 空」都在檔案裡,不靠省略時的預設;
3. 自己註冊 `asset` scheme 的拒絕 handler(見上),feature 被打開時內建也掛不上去。

測試(不開 webview)要證明的是:設定 `enable: false` 且 `scope` 空、Cargo 沒有 `protocol-asset`、`asset` scheme 的 handler 對 `learning/` 裡的檔回拒絕且不讀。真的 webview 打 `asset:` 沒量到,見文末。

## 3. `assetUrl` 怎麼產生 URL

**不用 `convertFileSrc`。TS 自己組自訂協定的 URL。**

`convertFileSrc`(tauri 2.11.5 `crates/tauri/scripts/core.js`,掛在 `window.__TAURI_INTERNALS__`):

```text
encodeURIComponent(filePath)
Linux:     `${protocol}://localhost/${path}`     預設 protocol = 'asset'
Windows:   `http://${protocol}.localhost/${path}`
```

不用它的理由:

- 預設協定是 `asset`,正是要關掉的那個。呼叫端若忘了傳協定名,URL 會指向內建協定。
- 它吃的是檔案系統絕對路徑,而且 `encodeURIComponent` 會把 `/` 編成 `%2F`。我們要的是相對 `learning/` 的路徑,解一次之後必須跟白名單檢查的字串逐位元相同。
- 它只存在於 webview 注入的 `__TAURI_INTERNALS__`。`assetUrl` 是同步簽名,測試與提示都不能靠那個全域。

產生的形式(Linux,本張唯一要做的平台):

```text
lc://localhost/<relPath 的每一段用 encodeURIComponent,段與段之間保留 />
```

例如 `cards/a.md` → `lc://localhost/cards/a.md`。handler 對 request path 解恰好一次,得到的字串就是當初檢查過的 `relPath`,再接到 `learning/` 根目錄。雙重編碼 `..%252f..%252fetc` 解一次仍含 `%`,白名單拒絕。

Windows 的 `http://lc.localhost/…` 留給 phase-5,本張不實作。

## 4. TS 側提示用哪一份檢查

**`apps/desktop/src/` 裡的一份 TypeScript 謄本,不是 Rust,也不呼叫 `recordEvent`。**

- 落點:`apps/desktop/` 的 owner 是 `10-desktop-shell`(`scripts/boundaries.owners.json`)。提示檔放這裡,不另開落點。
- 函式自己丟錯,不呼叫 `recordEvent`,不寫 `state/log.jsonl`。
- 權威仍是 `lc` handler:webview 真的請求該 URL 時,Rust 解一次、跑同一份白名單、不通過就拒絕。TS 謄本與 Rust 的 Unicode 版本可能不同(§13 已知限制);不一致時以 Rust 為準。
- 四個 command(`read` / `write` / `list` / `exists`)的拒絕才回 TS,由 TS 呼叫 `recordEvent`。那條 import 是另一條路,不是 `assetUrl` 的提示。

`recordEvent` 的落點(開工查的,不憑工單稿):

- 定義:`packages/core/src/schema/log.ts` 的 `export function recordEvent`
- 再出口:`packages/core/src/schema/index.ts`
- owner:`packages/core/src/schema/` → `01-data-layer`
- 既有呼叫寫法:`import { recordEvent } from '@core/schema/log.js'`
- `scripts/boundaries.allow.json` **沒有 `symbols` 欄**。檢查器只比 `from` / `to` / `reason`(見 `scripts/check-boundaries.ts` 的 `AllowEdge`)。10→01 的例外只能整邊放行;「symbol 只放 `recordEvent`」由 import 本身遵守(只 import 這個名字),檢查器擋不住同邊的其他 symbol。這點記在這裡,實作時不順便拉別的 01 symbol。

## 沒量到

真的 webview 請求(webkit 在把 URI 交給 handler 之前有沒有先解碼一次)沒量到。原因:這台是使用者的桌面,工單禁止開 GUI(`tauri dev` / webview)。內建 handler 自己還會 `percent_decode` 一次,所以 Tauri 的契約是「送到 handler 的 path 仍是編碼過的」。我們的測試會直接餵 `http::Request`(path 仍編碼)給同一個 handler 函式,不經過 webkit。若 webkit 在 Linux 上先解了一次,雙重編碼的現場行為會跟單元測試不同——這件事留在報告,不開視窗去量。
