## 一次採用走了三個模板版本

每一版都不是「模板變好了所以升」,而是**我們的守門在採用過程中抓到模板自己違反模板要推廣的規則**。

### v1.4.1 → P-83:模板的測試資料裡有可照抄的 Stryker CLI 字面

我們 `mutate.test.ts` §13 的「不准繞過鎖」掃描器掃 repo 裡**所有文字檔**,抓到模板
`check-doc-rot.test.ts:432` 有一句可照抄的指令 —— 它其實是 doc-rot 黑名單的**測試資料**,
不是指令,所以是**假陽性**。

worker **停下來問,沒有自己開例外**。它提的兩個選項:

- **B1**:`mutate.test.ts` 對帶 `SOURCE` 標頭的檔案開例外
- **B2**:回流模板,把測試資料拆成字串串接

**B1 被否決,兩個理由:**

1. **範圍太大** —— 「帶 SOURCE 標頭」= 三十幾個檔,等於掃描器一次讓出三十幾個檔,
   而真的有一句可照抄指令的模板檔就會靜默通過。
2. **「有 SOURCE 標頭」不等於「可信」** —— 它只等於「來自模板」,而模板是**同一種 agent 寫的**。
   用「來源」當豁免條件,跟用「作者是誰」當豁免條件是同一件事。

而且 **B2 正好是我們自己的先例**:2026-09-05 把 §13 從 md/json/sh 擴到所有文字檔那輪,
我們**刻意把掃描器自己的檔案留在範圍內、不開任何例外**,fixture 全部用字串串接建,
並加一條測試釘住「它們仍然拼得出真正的違規字串」。**模板犯的正是我們當時刻意避開的那件事。**

### v1.4.2 → 模板把我們的規則變成它自己的守門

修法比「改那一行」多兩層:

- `check-doc-rot.test.ts` 的 fixture 改**字串串接**,並釘住仍拼得出
- 出貨的 `doc-rot.blacklist.json` 那條 pattern 改成 regex(**語意相同、字面不可照抄**)——
  否則 sync 進來的 json 也會被抓,那是同一個問題的第二個現場
- **新增 `no-bypass-literal.test.ts`,掃模板 `scripts/` 全部文字檔、不豁免自己**

最後一條是關鍵:**把我們 §13 的規則回流成模板自己的守門**,所以下一個專案不會再收到同一顆地雷。

### v1.4.2 採用時 → P-84:模板兩支新守門自己不達標

我們的零輸入守門(ADR-045)抓到:

```
zero-input-guard > check-next-gates   > [missing] --root 不存在:指名有問題的那條路徑
zero-input-guard > check-phase-status > [missing] --root 不存在:指名有問題的那條路徑
```

worker 當時的建議裡有半句是「跑一次確認全部通過**或進基準**」。**後半被否決**,依據是
**ADR-045 Consequences 6**:

> **任何新增入口都必須先達標才能進 main** —— 基準只收「守門誕生前就存在」的洞,**不收新的**。

那一輪 20 個探針剛好有 2 個不過。**如果放行,那兩個洞會以「既有基準」的身分永久留下**,
而它們是當天才進來的。這條規則第一次生效抓到的是我們自己的 `degraded-report.ts`,
這次抓到的是模板 —— 兩次都是「**新東西不准用舊債的身分進來**」。

### v1.4.3 → 修的是類,不是那兩支

- `_root.ts` 加共用的 **`requireRootDir`**,**7 支**吃 `--root` 的守門在任何設定檔查找**之前**
  先確認目錄存在並指名路徑
- 模板**新增自己的零輸入守門**,列舉每支 `check-*.ts`,**新守門沒進清單就紅**

第二條的意思是:**下一支新守門會在模板端就被抓,不用等我們撞到。**

那 2 紅**自己消失,沒有開任何例外**。

## 流程上的事(記下來,不是抱怨)

`0998d12` **不是協調者合併的**。技術顧問在隔離簽出 `git merge --no-edit a2c6ee6` 產生它,
跑完 `check:all` 之後 `git push origin 0998d12:main`。

原因:main 當時已多了 `a2c6ee6`,直接推分支 tip `7ab8558` 會 non-fast-forward。

**顧問已認,並定下規則:**

> **顧問只推 fast-forward 得了的 sha;推不了就退回協調者合併,顧問不製造合併 commit。**

少掉的三件由協調者事後補:**合併後完整鏈**(11/11 綠)、**tag**(`template-143`)、
**理由鏈**(就是這份檔案)。

另外一件:顧問原本把「送驗後 main 凍結」那類通知送到 agent-bridge 的 duet 頻道,
**而協調者不在那個頻道**,所以那些通知根本沒收到。已改成雙向直接 `SendMessage`。
**又是一次「送出成功 ≠ 對方收到」。**
