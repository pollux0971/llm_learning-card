## 4. 做了什麼

壞行仍然只有一份定義:packages/core/src/llm/spend.ts 的 `parseLedger`。`readDailySpend`、scripts/llm-spend.ts、router 都已經經過它,沒有再開第二個判定的地方。公開簽章沒改。

判定順序(先修行號最小的那一行,不分哪一天,不先用 ts 濾今日):

1. 空白行略過(T8 不變)。
2. `JSON.parse` 失敗:維持「不是合法的 JSON」。
3. 不是物件(字串、數字、陣列、null):維持「不是 log 事件」。既有 llm-spend 測試要這句,跟 schema 失敗分開。
4. 物件沒過 `@contracts/index.js` 的 `LogEventSchema`:`bad.what` 含 `LogEventSchema` 與 schema 第一個錯誤訊息。空 ts 的訊息是 schema 自己的「ts 不可為空」,沒有在 spend.ts 再寫一份。
5. `type === 'llm_call'` 再加:
   - C1:`ts` 對上 `YYYY-MM-DDTHH:mm:ss`、可選小數秒、`Z` 或 `±hh:mm`(冒號必須有)。年月日丟回 `Date.UTC` 對回來,對不上就是被 `Date` 滾過的假日期(2026-02-30、非閏年 2 月 29 日)。小時 25、月份 13 在範圍檢查就拒。閏日 2028-02-29 放行。
   - C2:`tokens_in`、`tokens_out` 只要出現,就必須是非負的安全整數。null、字串、小數、布林、陣列、負數、Infinity、超過 `Number.MAX_SAFE_INTEGER` 都拒。
   - C3:計價行必須有非空字串 `provider`,以及 `tokens_in` 與 `tokens_out`。計價行 = `provider !== 'ollama'`(只認小寫,跟 `isLlmCallEvent` 一致)且不是標記行。標記必須剛好是布林 `true`(`timeout` / `truncated` / `retry`)。標記行與 ollama 免 C3,仍受 L、C1、C2。
6. 同一行多個欄位壞掉時,點名順序是 C1、再 C2(`tokens_in` 先於 `tokens_out`)、再 C3(`provider` 先於缺的 tokens)。`bad.what` 含違規欄位名。

沒有動 `computeDailySpend` / `numberField`。截斷行只有 `tokens_out`、輸入端當 0 的既有低估留著,witness `llm.spend.tokens-missing-zero` 沒有刪。沒有出現 `EVENT_TYPES` 或事件類型字面清單。
