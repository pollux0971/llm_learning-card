## 給顧問判

### F1:有合成器時,黏底那一塊在螢幕上跟面板不同色

| | 檢查器截圖 | 螢幕上(framebuffer) |
|---|---|---|
| 面板(`.hud-body` 左內距) | `#ffffff` | `#e6ecf3` |
| 黏底那一塊 | `#fefeff` | `#fefeff` |
| 每通道差 | 1、1、0 | 24、18、12 |

- 面板是 `var(--hud-panel)`(`rgba(255, 255, 255, 0.9)`,`../../packages/ui-shared/src/hud/hud.css:109`),疊在視窗後面的東西上。巢狀 GNOME 的桌面是 `#023c88`,九成白疊上去是 `#e6ecf3`。真的桌面會看桌布:黑桌布時面板是 `#e6e6e6`(算的,沒量)。
- 黏底那一塊是 `var(--hud-solid)` 加 `::before` 的 `var(--hud-panel)`(`../../apps/teach-card/src/App.svelte:458`),不透明的 `#fefeff`,跟桌布無關。
- 檢查器的 `Page.snapshotRect` 不畫桌面,底是白的,所以那裡只差 1。
- 沒有合成器時兩個都是 `#fefeff`,差 0。工單算的對。
- 看起來的樣子(`sheet49a`、`cmp-U150`):淡藍灰的面板底部有一塊白的按鈕底座,邊緣清楚。例子框(`#f4f6f8`)本來就是一塊不透明的框,所以畫面上已經有這種塊。
- 兩條路:
  - **A. 收。** 透字與漏線這兩個問題已經解了。工單第 1 條有合成器那一半的「`#ffffff`」改成「檢查器截圖」,或寫明螢幕上會跟桌布有關。
  - **B. 開新工單。** 讓內容捲到黏底那一塊上緣就被切掉,黏底那一塊才能用跟面板一樣的半透明,任何桌布都同色。要再一輪實作、測試、`@manual`,而且會動到 T47 的版面(黏底、T35 提示的留白)。
  - **我建議 A**:看起來是刻意的按鈕底座,不像畫壞。

### F2:X11 捲到底時按鈕往上 1.29 px

| | 捲到中間 | 捲到底 | 差 |
|---|---|---|---|
| `.dock` 上緣 / 下緣 | 343.45 / 471.00 | 342.16 / 469.70 | 1.29 |
| 按鈕上緣(頁面座標) | 355.45 | 354.16 | **1.29** |
| 按鈕黑框上緣(螢幕第幾排) | 355 | 354 | 1 排 |
| 黏底那一塊下緣離看得到範圍下緣 | −0.03 | 1.27 | |

- 100%、150%、短卡 A 在 150%,數字都一樣。有合成器與沒有合成器一樣。
- Wayland 是 301.30 / 301.16,差 0.14 px、螢幕上 0 排。提示在時 `.hud-body` 的 `padding-bottom` 有 54.16 px,多蓋的 1 px 在留白裡面。
- T47(`42bbcb2`)同一個量法是 0.29 px(`T47-manual-2026-10-24.md` 的 M4)。
- **原因(量過)**:`.dock::before`、`.dock::after` 的 `inset: 0 0 -1px 0` 往下多蓋 1 px,這 1 px 在 WebKitGTK 裡也算進可以捲的範圍。只在這個頁面用 CSSOM 把兩個偽元素的 `bottom` 改成 0(探針,沒有改檔):
  - `scrollHeight` 從 4889 變 4888;
  - 捲到底時黏底那一塊離下緣從 1.27 變 0.27;
  - 按鈕位移從 1.29 變 0.29;
  - 把那條規則刪掉,又回到 4889 / 1.27 / 1.29。
  - 只拿掉多蓋的 1 px 會讓 Wayland 提示上面那一排再露出來(它就是為那一排加的),所以這不是修法,只是證明原因。
  - X11 不需要多蓋:捲到中間時黏底那一塊本身已經超過看得到的下緣 0.03 px;捲到底時下面沒有內容了。要多蓋的只有 Wayland 提示上那一排。
- 自動測試沒抓到:T47 的 c 比按鈕位置的容差在 `21c0e18` 放寬到 1.5 px(顧問 2026-10-25 為 T49 裁的,`../../apps/teach-card/src/t47-zoom-layout-render.test.ts:595` 的註解寫「差 ≤ 1 px」),1.29 在 1.5 裡面。
- 兩條路:
  - **A. 收。** 螢幕上只差 1 排,跟裁容差時預期的 1 px 一樣。
  - **B. 修。** 多蓋的那一塊只在 Wayland 提示在的時候需要;X11 不多蓋,位移就回到 0.29 px。量法照這份(WebKitGTK 真 app)。
  - **我建議 B**:顧問的線是 ≤ 1 px,現在是 1.29;這 1 px 是多蓋帶來的,不是 T35 的留白逼出來的。
