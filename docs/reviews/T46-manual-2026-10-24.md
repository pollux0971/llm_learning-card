## 量法

### 暫存根與卡

- 暫存根複製 `contracts/fixtures/learning-minimal`,另寫卡、題目、圖。真的 learning/ 只讀、前後各量一次。
- 暫存根的 `assets/` 放 4 張 PNG(量測腳本自己畫的色塊,看得出方向與有沒有被裁):寬圖 1200×300、高圖 240×960、小圖 24×16、中文檔名 480×240。故意不放第 5 張(不存在的那張)。
- 主流程第一張卡(下面叫卡 A):一個例子,裡面有寬圖與中文檔名的圖;內文(例子外面)另有小圖。
- 第二張(卡 B,沒有子卡,按深入會生成):三個例子:
  - 例子 1:高圖;
  - 例子 2:小圖、不存在的那張;
  - 例子 3:會被拒絕的四個路徑:`raw` 底下、`https:`、`data:image/png`、含 `"` 與 `<b>` 的路徑。
- 其他主流程的卡各一個只有字的例子(重開 app 時不管停在哪張,都有例子可以看)。
- 假網路:在線、每個模型呼叫延遲 4 秒(生成中那一行留得夠久,好按「取消」)。`.env` 是假金鑰,跑完刪掉。**LLM 真呼叫 0。**

### 每一幀

做法同 T45:教學卡頁面裡裝一支小程式,在每一個畫面幀(`requestAnimationFrame`)與每一次 DOM 變動(`MutationObserver`)都記一筆(去重)。這次另外記:

- 每個例子開或收(`details.open`),以及內容看不看得到。
  - WebKitGTK 收起來的 `details`,內容的 `getClientRects()` 仍然有值,不能拿來判斷。
  - 改用「有一個子元素 `checkVisibility()` 為真而且高度 > 0」,並且另量例子框的高度。
- 放大層的矩形。

「其他例子有沒有變過」與「第一幀是不是收的」,都是拿這份每一幀的紀錄算的,不是只看動作前後兩個點。

### 請求

- 頁面這邊:檢查器的 Network 記每一個請求(`review`、`lc://`、`ipc://`)。
  - 開 app 時第一張卡的圖,在檢查器接上之前就載完了,Network 看不到。
- Rust 這邊:另外用 inotify 記暫存根 `assets/` 底下每一次開檔。`lc` 協定每服務一次請求就開一次檔。
- 帳本:暫存根的 `state/log.jsonl`(拒絕會寫 warning)與 app 的 log。

### 真的動作

- 指標:XTest 只送 `:97`(送別的 DISPLAY 工具會拒絕,開跑前試過 `:1` 被拒)。
- 鍵盤:XTest 送 Return、空白鍵、Esc。
- 視窗大小:對 `:97` 上的教學卡視窗送 `XResizeWindow`,由巢狀 GNOME Shell 決定。
- 滾輪:XTest 的按鍵 4 / 5。
- 「捲到看得到」是用 `scrollIntoView` 或設 `scrollTop` 準備的;動作本身都是真的指標或鍵盤。

### F1:手動收放過之後按深入,整張卡重畫(缺陷)

另外開一次 app,專門重現。卡 B 進來時三個都是收的,html 是用 storage `0` 畫的。

| | X1 | X2 |
|---|---|---|
| 按深入之前 | 只開例子 2(010);最後按的是「開」,storage `1` | 010;最後按的是「收」,storage `0` |
| 真指標按「深入這個」之後 | **按下後 145 ms 內三個全開(111)** | **例子 2 自己收起來(000)** |
| 卡片高度 | 625 → 1926 px | 625 → 449 px(`scrollTop` 192 被壓成 16) |
| 按鈕 | 從 y 339 跳到 1640(中間有一幀到 1649),看得到的範圍是 38–471:**按鈕被推出畫面** | 0 px(卡變短、捲動被壓回) |
| 生成中那一行 | 1686–1748,**在畫面外**;「取消」要先捲過去才按得到 | 看得到 |
| 不存在的圖 | 再要一次(404 多 1 則 console) | 再要一次 |
| 按取消之後 | 還是 111 | 還是 000 |

原因(我讀程式碼的推論,不是量出來的;上面的現象是量出來的):

1. `../../apps/teach-card/src/App.svelte` 第 61 行 `shown = $derived(parsed())`,而 `parsed()` 在第 53 行讀 storage 決定 `examplesOpen`。
2. 第 22–23 行每次 `pull()` 都換一個新的 `view`,所以同一張卡上任何一次 `pull()`(深入、取消、輪詢)都會重跑 `parsed()`,重讀 storage。
3. 只要從這張卡畫出來之後按過標題,storage 就跟當初畫 html 時不一樣,html 字串跟著不同。
4. Svelte 的 `{@html}` 字串不同就整塊換掉,於是每個例子都被設成「最後按的那一下」。
5. 「找不到圖片」的字樣也被換回 `img`,再要一次,404 之後才再換成字樣。這一換一回就是上面 9 px 那一幀。

為什麼自動測試沒抓到:渲染測試 b 只量「按一個標題,其他不變」。沒有測試在「手動收放之後」做會 `pull()` 的動作(深入、取消、深入錯誤)。T45 的渲染測試用的卡沒有收放過,所以照樣綠。

- 補一條渲染測試:手動收放到跟記住的狀態不同 → 深入 → 生成中 → 取消,每一幀:
  - 別的例子沒變;
  - 按鈕 0 px;
  - 不存在的圖沒有再被要。
