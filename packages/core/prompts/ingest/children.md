# ingest.cards — 父卡 → level 1 子卡

你會收到一張已經存在的教學卡(parent_id、parent_title、body),當作「父卡」。
為它產出更深入的子卡。每張子卡只講一個父卡 body 沒有直接講完的機制、觸發條件、邊界或細節。
回傳一個 JSON 陣列,每個元素長這樣:

```json
{
  "title": "簡短標題",
  "body": "卡片正文,純 markdown,不要包含 example 圍欄",
  "examples": ["0 到 1 個具體範例,示範這張子卡新加的那一點"]
}
```

規則:

- 回傳 2 或 3 個元素,一個元素一張子卡。不要回傳空陣列,也不要只回 1 張。不重述不等於不產出
- 刪掉這張子卡之後,父卡 body 仍教不會這一點,才算新的。一張子卡只講這一點
- 父卡 body 已經斷言的主張,換個標題或只補一個標頭名,仍是重述,不要出。
  例:父卡已寫「帶憑證時必須指名來源,不能用萬用字元」,不要再出「憑證請求不能搭配萬用來源」。
  父卡已寫「結果可以快取、少一趟往返」,不要再出「快取時間」
- 父卡點到主題、但沒寫完的標準細節,要出,不要因為正文沒點名就整張砍掉:
  - 父卡說換埠就不同源,但沒說省略埠與寫上預設埠(HTTP 80、HTTPS 443)是否仍同源 → 出「預設埠的比較」
  - 父卡說有些跨來源請求會先問伺服器,但沒點名哪些方法或內容類型會觸發,也沒寫 OPTIONS 與 Access-Control-Request-* 怎麼交換 → 這兩點各出一張
  - 父卡說沒有這條規則,別的網站就能讀到銀行回應 → 「請求仍可能送出,但腳本讀不到回應」是界線,要出
  - 父卡說網頁不能自己宣稱有權限,但沒說在請求裡自己加允許來源的標頭沒有用、瀏覽器只看回應 → 這條界線可以出
- 不要出另一個主題的前置定義。父卡在講伺服器如何授權跨來源讀取時,不要另出「來源由協定、主機、埠組成」
- 若輸入在 body 之前有 `already_covered:`(同分類已有父卡的標題與一句摘要),那些主張已經有卡,連換標題也不要再寫。沒有這個區塊時,就以你收到的父卡 body 為準
- title 不要與 parent_title 相同。不要逐字抄父卡的句子
- body 上限 100 字。字數規則:CJK 每字算 1;英數字的連續序列算 1(連字號、句點、
  空白、撇號等標點會切斷序列,例如 `same-origin` 算 2、`1.3` 算 2);標點與符號本身算 0。example 圍欄不算字數
- 子卡沒有自己的原始素材(不是切自 raw),不用附行號
- 只回傳 JSON 陣列,不要加任何說明文字或 markdown 圍欄
