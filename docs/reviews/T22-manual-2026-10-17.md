### 怎麼呼叫(不經畫面)

- `review-client.ts` 還沒接進任何頁面(那是 T24),所以頁面裡沒有 client 可以叫。
  改成經檢查器對考試卡那一頁 `Runtime.evaluate`,呼叫 client 預設走的同一個 `window.__TAURI_INTERNALS__.invoke('review', { request })`,
  `request` 的形狀照 client:`{ v: 1, id, method, params }`,`id` 從 1 往上數,`params` 是 `{}`。
- 檢查器的 `Runtime.evaluate` 不等 Promise,所以分兩步:先送出、把結果存在 `window` 上,再每 50 ms 讀一次。
- live 的輪次只叫 `start`、`next`、`status`,**不叫 `submit`**:批改是唯一會呼叫 router 的地方(`grade-apply.ts`、`grade-fill.ts` 的 `router.call`),`start` / `next` 不會。

### 怎麼看 `hello`

`hello` 由 Rust 收下(`wait_hello`),不轉給 webview,所以從頁面看不到。外包 strace 的 3 輪在 app 的 `PATH` 最前面放一個 `node`,
內容是 `exec strace -f --seccomp-bpf -e trace=write,writev,connect -e signal=none -s 8192 -o <暫存根>/out/strace.log <真的 node> "$@"`,
從側車寫 fd 1 的那一行讀出 `hello`。這 3 輪的行程樹是 app → strace → node,側車環境多一個 `PWD`(是外包的 `/bin/sh` 加的;沒外包的 6 輪沒有)。

### 第 2 列:假 router 的字樣

app stderr(Xvfb 沒有 DRI3 的兩行 libEGL 警告以外)就只有這幾行:

- 第 1、8、9 輪各兩行 `[review-sidecar] [review-sidecar] 正在用假 router`(原本的側車一行、第 6 列重起的側車一行);第 2 輪一行。
- live 的第 3–6 輪:沒有任何 `[review-sidecar]` 行。第 7 輪一行 `[review-sidecar] [review-sidecar] router-unavailable`。

### 第 3 列:沒有真呼叫

- 這個簽出沒有 `.env`,側車的 `_env.js` 讀不到任何檔(它只讀 `<repo>/.env`)。
- 側車的環境(`/proc/<側車>/environ` 只取鍵名):live 那幾輪是 `HOME LANG PATH USER XDG_CACHE_HOME XDG_CONFIG_HOME XDG_DATA_HOME XDG_STATE_HOME`;
  假 router 那幾輪多一個 `LC_REVIEW_FAKE_CLOUD`(debug build 才帶,照工單)。四個假金絲雀 9/9 輪都不在,白名單以外的鍵 0 個(外包輪的 `PWD` 除外,見上面)。
- 外包 strace 的 3 輪:側車的 `connect` 只有 3 次 `AF_UNIX`,都是 tsx 找自己父行程的 IPC pipe(`/tmp/tsx-1000/<pid>.pipe`,ENOENT);`AF_INET` / `AF_INET6` 0 次。
- 每一輪 `start` 之後 `ss -tunap` 找不到側車 pid 的任何 TCP / UDP。
- 9 輪暫存帳本 `state/log.jsonl` 都是 0 bytes(一行 `llm_call` 都沒有)。

### 第 5 列:量法

第 3 輪是先 `wait` 到 app 被收掉才開始看,側車那時已經不在(記成 0 ms,較粗)。第 4、5 輪改成送 SIGKILL 之後立刻每 1 ms 看一次 `/proc/<側車>/stat`:34 / 33 ms。
第 5 輪外包 strace,側車那個 node 的結束是 `+++ exited with 0 +++`:是讀到 stdin EOF 自己結束,不是跟著被砍。

### 第 6 列:細節

- SIGKILL 側車之後等 300 ms,再叫 `status` 兩次:第一次 `invoke` 被拒,拒絕值是 `{ kind: "sidecar-exited" }`;第二次 `{ v: 1, id, ok: true, result: { paused: false, today } }`。
- 第二次之後側車剛好 1 個,pid 跟被砍的不同,父行程是 app。被砍的那個 pid 在 `/proc` 已經不在(Rust 的 `stop` 有 `wait`,沒有殭屍)。
- 之後關 app,app exit 0,重起的那個側車也一起收掉。

### 第 7 列:比對了什麼

- 針:主簽出 `.env` 裡值不少於 8 個字元的 5 個鍵(`OPENAI_API_KEY`、`GATEWAY_API_KEY`、`GATEWAY_BASE_URL`、`LLM_CLOUD_MODEL`、`LLM_LOCAL_MODEL`)各取前 8 個字元;
  比 8 個字元短的 4 個鍵(`LLM_CLOUD_PROVIDER`、`LLM_DAILY_CAP_USD`、`LLM_PRICE_IN_PER_M`、`LLM_PRICE_OUT_PER_M`)不比(短值到處都會撞到,也不是秘密)。另外加 3 個假金絲雀的整串值。
- 草堆(每一輪):`app.err`、`app.out`、暫存 `state/log.jsonl`、檢查器拿到的每一個回應;外包 strace 的 3 輪再加 `strace.log`(側車對任何 fd 的每一次 write / writev,每輪約 650 KB)。
- 結果:9 輪、每個來源、每根針都是 0 次。正對照:同一段比對程式對一串人工放進針的字串,真值前綴與金絲雀都數得到 1 次。
- 值只在比對程式的記憶體裡,沒有印出、沒有寫進任何檔。

  兩邊都照工單做,是規格(我)沒對齊。工單的過關條件「有 `[review-sidecar] 正在用假 router`」照字面是有的。要改的話一邊拿掉就好(例如 Rust 遇到已經是這個前綴開頭的行不再加);建議等 T24 碰到 stderr 時順手,不另開工單。請顧問決定。
- **O2 `hello` 從頁面看不到。** Rust 收下 `hello` 不轉給 webview(照工單),所以「`hello.fakeCloud`」只能從行程外面讀(這次用 strace)。`start` 的結果另外帶了 `fakeCloud`,頁面要知道的話看那個就好。只是量法的註記。
