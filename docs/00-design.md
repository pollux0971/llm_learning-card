# 桌面學習卡片系統 — 設計文件 v1

> 本文件是四輪問答後的共識整理。目標讀者是「要動手建這套系統的人或 LLM agent」,
> 讀完應該不需要回頭看對話紀錄就能開工。

---

## 0. 一句話

兩張常駐桌面的小卡片:**教學卡**每次教一個 100 字內的概念(由你拉、不是它推),
**考試卡**用固定的 1 / 7 / 30 / 90 / 180 天骨架考你昨天、上週、上月、上季、半年前學的東西,
題型只有填空與應用兩種,由 LLM 審核;答錯退回起點。內容來自你的 raw 資料,沒有才由 LLM 補。

---

## 1. 範圍

### v1 做

- 兩張獨立視窗的卡片:教學卡、考試卡
- 多類別(語言、資安、coding 工具……),類別之間彼此獨立
- 記憶型內容(需要靠複習才記得住的東西)
- Linux 桌面

### v1 不做

- **時令型內容**(例如桃樹的季節管理):不適合間隔重複,需要另一種「日曆驅動」的卡片型別,等記憶型跑穩再加
- macOS、Windows(依序在 v1 之後)
- 跨機器同步(暫用 git 手動處理)
- 通知 / 提醒時間
- 自適應排程(FSRS):排程層設計成可替換模組,之後想切再切

---

## 2. 架構

四層,每層只有一個職責,層間用檔案系統溝通。

```
┌─────────────────────────────────────┐
│ 介面層  Tauri 2 + Svelte + TS        │  兩個視窗、系統列、渲染 markdown
├─────────────────────────────────────┤
│ 排程層  固定骨架 + 錯誤回退           │  純函式,無外部依賴
├─────────────────────────────────────┤
│ LLM 層  本機 (Ollama) + 雲端 API      │  依任務路由,見 §7
├─────────────────────────────────────┤
│ 資料層  markdown + JSON,git 版控      │  卡片、題目、狀態、依賴圖
└─────────────────────────────────────┘
```

**為什麼不整合現成專案**:Anki / SiYuan / Logseq 各有自己的資料模型與執行環境,
「放同一資料夾接線」實際上等於重寫。這裡只借用「概念」,不借用「程式」。
因為選了固定骨架,連 FSRS 函式庫都不需要。

## 3. 資料層

### 3.1 目錄結構

```
learning/
├── raw/                    # 原始素材,唯讀,你放進來
│   ├── 語言/
│   ├── 資安/
│   └── coding工具/
├── cards/                  # LLM 產生的教學卡
│   ├── 語言/
│   ├── 資安/
│   └── coding工具/
├── questions/              # 每張卡對應的考題(與卡片同 id)
├── assets/                 # 圖片
├── state/
│   ├── reviews.json        # 每張卡的複習狀態
│   ├── weekly.json         # 週目標進度
│   └── log.jsonl           # 所有事件的流水帳
├── graph/
│   └── deps.json           # 依賴圖(按類別)
├── SCHEMA.md               # 給 LLM agent 看的規則檔
└── scripts/
    ├── ingest.py           # raw → cards + questions + deps
    ├── due.py              # 列出今天到期的題目
    └── lint.py             # 健檢
```

### 3.2 教學卡格式

一個概念一個檔案。frontmatter 是機器讀的,body 是人讀的。

```markdown
---
id: sec-0042
category: 資安
title: 同源政策
level: 1                      # 0 = 入門, 1 = 第二層, 2+ = 即時生成
parent: sec-0031              # level 0 的卡沒有這欄
prereqs: [sec-0012, sec-0019] # 先備概念,可為空
source: raw                   # raw | llm
source_ref: raw/資安/web-security-basics.md#L120-L145
provisional: false            # 本機模型即時生成的卡為 true,待雲端複審
created: 2026-09-02
---
瀏覽器限制一個網頁的程式碼只能存取「同源」的資源。
同源 = 協定、主機、埠號三者完全相同。這是防止惡意網站
讀取你在其他網站上資料的第一道牆。

```example
https://a.com/page 與 https://a.com/api → 同源
https://a.com 與 http://a.com → 不同源(協定不同)
https://a.com 與 https://a.com:8443 → 不同源(埠號不同)

![同源判定流程](../../assets/sec-0042-sop.png)
```
```

規則:

- **body 上限 100 字**(中文字、英文單字各算 1;標點不算)。ingest 時硬檢查,超過就退回重生。
- **範例放在 ` ```example ` 圍欄內**,不計字數、不限長度。渲染器把這種圍欄當成「巢狀 markdown 容器」而不是程式碼,所以裡面的圖片、清單、粗體都會正常渲染。
- 一張卡可以有多個 ` ```example ` 區塊。
- 圖片放 `assets/`,用相對路徑引用。
- 卡片右上角依 `source` 顯示小標示;`provisional: true` 另加一個「待複審」標示。

### 3.3 考題格式

每張卡對應一個題目檔,ingest 時**事先產好**,所以 D1 考試離線可用。

```yaml
# questions/sec-0042.yaml
card: sec-0042
fill:                                   # 填空題,2-3 個變體輪流出
  - prompt: "同源的判定條件是___、___、___三者相同。"
    answers: [["協定", "protocol", "scheme"],
              ["主機", "host", "域名", "domain"],
              ["埠號", "port", "埠"]]
  - prompt: "https://a.com 和 http://a.com 是否同源?___"
    answers: [["否", "不同源", "不是", "no"]]
apply:                                  # 應用題,1-2 個變體
  - prompt: "你在寫一個前端,要呼叫 https://api.example.com,
             但網頁在 https://app.example.com。會遇到什麼問題?怎麼解?"
    rubric:
      - "有指出這是跨來源(cross-origin)"
      - "有提到 CORS 或等價的解法"
      - "沒有事實錯誤"
```

```

### 3.5 依賴圖

```json
// graph/deps.json
{
  "資安": {
    "nodes": ["sec-0012", "sec-0019", "sec-0031", "sec-0042"],
    "edges": [["sec-0012", "sec-0042"], ["sec-0019", "sec-0042"]]   // [先備, 後學]

```

## 4. 教學卡

### 4.1 外觀與操作

- 常駐置頂小視窗,預設 360 × 480,可縮放、可滾動、記住位置
- 上方:類別名稱、`source` 標示、level 標示
- 中間:body(100 字)+ 範例區塊(可折疊)
- 下方三個按鈕:
  - **下一個** — 依 §4.2 順序取下一張 level 0 或 level 1 的卡
  - **換類別** — 切到另一個類別的下一張
  - **深入這個** — 進入目前這張卡的子概念(§4.3)
- 按「下一個」或「換類別」時,目前這張卡標記為 `learned`,進入複習排程(stage 0 → 1,`next_due` = 明天)
- 沒有「今天學幾個」的上限,由你自己控制。但介面上會顯示「今天已學 N 個,明天將有約 M 題」作為提醒。

### 4.2 順序

同類別內按**依賴圖拓樸排序**:先備概念一定排在依賴它的概念之前。
同一層級內無依賴關係的,以 raw 來源的順序當 tiebreaker。

這是**軟性順序,不是硬性閘門**:你可以透過「深入這個」跳到先備尚未學完的卡,
此時卡片頂部顯示一行「先備:X、Y(尚未學習)」,但不阻擋。

### 4.3 深度

- **level 0 與 level 1 在 ingest 時就預先產好**(雲端模型)。這兩層涵蓋日常九成的使用。
- **level 2+ 按「深入這個」時即時生成**:
  - 有網路 → 雲端模型,`source: llm`,`provisional: false`
  - 無網路 → 本機模型,`source: llm`,`provisional: true`
  - 有網路時執行 `lint.py` 會找出所有 `provisional: true` 的卡,一鍵用雲端重生覆蓋
- 子概念一律 `source: llm`(因為它是從父概念延伸出來的,不直接對應 raw)

### 4.4 內容來源規則

- 有 raw → 從 raw 產生,`source: raw`,帶 `source_ref` 指回原文位置
- 沒 raw → LLM 依類別與主題名稱產生,`source: llm`
- **類別級開關** `require_raw: true`:該類別沒 raw 就不產卡,寧缺勿假。建議資安類別預設開啟。

## 5. 考試卡

### 5.1 排程骨架

| stage | 名稱 | 距上次通過 | 題型 |
|---|---|---|---|
| 1 | D1 | 1 天 | 填空 |
| 2 | D7 | 7 天 | 填空 1 題 + 應用 1 題 |
| 3 | D30 | 30 天 | 應用 |
| 4 | D90 | 90 天 | 應用 |
| 5 | D180 | 180 天 | 應用 |
| 6 | 歸檔 | — | 不再考,卡片併入 wiki 供查閱 |

題型對應記憶深度:剛學完考「能不能回想出關鍵詞」,久了考「能不能在新情境下用出來」。

### 5.2 錯誤處理

- **答錯** → `stage` 退回 1,`next_due` = 明天,`fails_in_row` +1
- **連續錯 2 次** → 除了退回 D1,教學卡隔天優先出這張卡的**縮短版**(LLM 重寫成 50 字內、只保留最核心的一句 + 一個範例),而不是原卡再看一次
- **連續錯 3 次以上** → 標記 `stuck`,lint 時列出來,由你決定是重寫卡片、拆概念、還是先跳過

### 5.3 每日上限與優先序

- 每天最多出 **10 題**,可調
- 超過的順延到隔天
- 優先序 = **逾期比例**(逾期天數 ÷ 該 stage 的間隔天數),高者先考。
  一張 D1 的卡晚一天是逾期 100%,一張 D180 的卡晚一天是 0.5%,前者記憶最脆弱,理當先考。

### 5.4 審核路由

**填空題**,三層,前兩層零成本零延遲:

1. 正規化(去頭尾空白、全形轉半形、英文轉小寫)後**精確比對** `answers`
2. **模糊比對**:長度 ≥ 4 的答案允許 1 個字元的編輯距離
3. 都不中 → **本機模型**判斷「是否為同義答案」,回傳 yes/no

**應用題**,需要判斷力:

- 有網路 → **雲端模型**,依 `rubric` 逐條判斷,全部通過才算過
- 無網路 → **本機模型**,同樣流程,但結果標記 `grader: local-provisional`;下次有網路時補一次雲端複審,若複審結果不同,以雲端為準並修正 stage

審核回傳格式固定:

```json
{"pass": false, "criteria": [true, false, true], "feedback": "有指出跨來源問題,但沒提到 CORS 這個解法。"}
```

`feedback` 一句話,直接顯示在卡片上,不解釋、不鼓勵、不廢話。

### 5.5 外觀

- 與教學卡同尺寸,獨立視窗,可分開擺
- 頂部顯示「今日 3 / 10 題,逾期 0」
- 每題:題目、輸入框(填空為單行,應用為多行)、送出
- 送出後:過 / 不過、一句話 feedback、下一題按鈕
- 全部答完顯示今天的小結:通過幾題、退回幾題、明天預估幾題

## 6. 週目標

- 計量:**本週新學的概念數**
- **防灌水規則**:一張卡要**通過 D1 考試**才算入本週計數。只按「下一個」滑過去不算。
  這是為了避免「一天猛按二十張、隔天考不完、下週歸零」的失敗模式——
  計數方式已依你的選擇定為新學數,這條規則是我加的護欄,不同意可拿掉。
- 目標值:預設每週 **7**,可調
- 週一歸零;達標後卡片頂部顯示一個小標示,不彈窗、不慶祝
- 不做連續天數,某週沒達標就是沒達標,下週重來,沒有任何懲罰

```json
// state/weekly.json
{"week": "2026-W36", "target": 7, "learned": 4, "passed_d1": 3}
```

## 7. LLM 路由表

| 任務 | 首選 | 備援 | 備註 |
|---|---|---|---|
| ingest:產生 level 0/1 卡片 | 雲端 | 無(等有網路) | 品質與幻覺風險最高處,不妥協 |
| ingest:產生考題 | 雲端 | 無 | 同上 |
| ingest:建依賴圖 | 雲端 | 無 | 同上 |
| 深入這個(level 2+) | 雲端 | 本機,標 provisional | |
| 填空審核 | 精確 / 模糊比對 | 本機 | 幾乎不用 LLM |
| 應用審核 | 雲端 | 本機,標 provisional | |
| 縮短版重教 | 雲端 | 本機 | |
| lint | 雲端 | — | 手動觸發 |

雲端模型透過環境變數指定 provider 與 model;本機透過 Ollama 的 HTTP API。
兩者都走同一個 `llm.call(task, prompt)` 介面,路由邏輯集中在一個檔案。

## 8. 技術棧

| 層 | 選擇 | 理由 |
|---|---|---|
| 桌面框架 | **Tauri 2** | 比 Electron 輕一個量級;Linux 系統列支援好;Mac / Windows 是同一份程式碼重編 |
| 前端 | **Svelte 5 + TypeScript** | 小型 widget UI 適合;無 virtual DOM 開銷 |
| Rust 層 | 只做 Tauri 必要的事 | 視窗、系統列、檔案存取、開機自啟。業務邏輯不放這裡 |
| 業務邏輯 | TypeScript | 排程、審核路由、狀態讀寫。你和 LLM agent 改起來快 |
| markdown 渲染 | markdown-it + 自訂 ` ```example ` 插件 | |
| ingest / lint 腳本 | Python | 獨立於桌面程式,可從 Claude Code 直接呼叫 |
| 版控 | git | 整個 `learning/` 目錄就是一個 repo |

### Linux 注意事項

- **Wayland**(GNOME 預設):應用程式無法自行設定置頂,需靠桌面環境的視窗規則。GNOME 需要擴充套件;KDE 可在視窗規則裡設。X11 無此問題。
- 系統列在 GNOME 需要 AppIndicator 擴充套件。
- 這兩點影響 Linux 版的體驗,不影響設計。

## 9. 建置順序

每個里程碑結束都要「能用」,不是「寫完」。

| # | 里程碑 | 完成定義 |
|---|---|---|
| M1 | 資料格式 + ingest | 丟一份 raw 進去,產出符合 §3 格式的卡片、考題、依賴圖。**沒有 UI,純 CLI**。用 Obsidian 或任何 markdown 檢視器看結果 |
| M2 | 考試卡 | 能列出今日到期題目、作答、審核、更新狀態。這是整套系統的核心,沒它就沒有間隔重複 |
| M3 | 教學卡 | 三個按鈕、依賴順序、深入生成、learned 標記 |
| M4 | 週目標 + 系統列 + 開機自啟 | 日常可用 |
| M5 | lint + provisional 複審 | 長期健康 |
| M6 | macOS | |
| M7 | Windows | |

M1 完成後就該開始餵真的資料,不要等 UI。M2 完成後就該開始每天用。

## 11. 決策紀錄

| 決策 | 選擇 | 被放棄的選項 | 原因 |
|---|---|---|---|
| 排程 | 固定骨架 + 錯誤回退 | FSRS 自適應 | 可預期性優先;排程層可替換 |
| 每日學習量 | 由使用者控制 | 固定 N | 使用者要主動權 |
| body 字數 | 100 字,範例不計 | 200 / 300 | 使用者要求 |
| 深入內容時機 | 預生兩層 + 更深即時 | 全預生 / 全即時 | 離線可用性與彈性的平衡 |
| 內容來源 | raw 優先,LLM 補 | 只用 raw / 只用 LLM | 兼顧覆蓋率與可信度 |
| LLM 位置 | 本機 + 雲端都要 | 單一 | 使用者要求 |
| D30 後 | 繼續 D90、D180 | 歸檔 / 併回 wiki | 使用者要求 |
| 遊戲化 | 每週目標 | 連續天數 / 不做 | 避免斷鏈放棄效應 |
| 週目標計量 | 新學概念數(需過 D1) | 天數 / 題數 | 使用者選新學數;D1 條件是護欄 |
| 教學順序 | 依賴圖拓樸排序 | raw 順序 / 隨機 | 先備知識優先 |
| 平台順序 | Linux → macOS → Windows | | 使用者要求 |
| 技術棧 | Tauri 2 + Svelte | Electron | 輕量、跨平台成本低 |
| 時令型內容 | v1 不做 | | 不適合 SRS,需另一種卡片型別 |
