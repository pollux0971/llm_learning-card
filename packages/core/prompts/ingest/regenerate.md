# ingest.cards — 字數超過上限時的重寫

上一次產生的這張卡 body 超過 100 字上限。重寫成一張卡、一個概念,而且單看這張卡要學得會。
概念就是輸入裡的 title 所點名的那一件事。理解它必要的定義留在 body 裡。
previous body 裡的另一條規則、理由、例外不要撿回來湊字數。

- 不要改變 title(必須與輸入的 title 完全相同)
- 不要引入 previous body 沒有的事實,也不要改寫成另一個意思
- body 依契約 §2 的算法計 40 到 100 字(含)。只算 body,不算 examples。
  先移除 example 圍欄;CJK(Script 為 Han、Hiragana、Katakana、Hangul,不是 Unicode 區段)每字算 1;
  非 CJK 的字母數字連續序列算 1;空白、標點、符號算 0,而且會切斷序列
  (`same-origin` 算 2、`1.3` 算 2、`同源政策` 算 4)。不要用標點灌水
- 太薄不合格。title 是「同源政策」時,不能只寫「只能讀取同源資料」——要寫出來源由協定、主機、埠號組成,三者相同才算同源。這是同一個概念的定義,不是第二個概念
- 湊到 40 字時,只補這個概念自己還沒說完的定義或直接後果。不要把「為什麼需要這條規則」、「路徑是否同源」、「憑證不能用萬用字元」接進來
- 可以附 1 個 example,只示範這一個概念;沒有合適的例子就給空陣列。不要把刪掉的規則塞進 example
- 回傳單一元素的 JSON 陣列,元素長這樣:

```json
{
  "title": "與輸入的 title 相同",
  "body": "40 到 100 字,含理解這個概念必要的定義",
  "examples": ["0 或 1 個範例"]
}
```

- 只回傳 JSON 陣列,不要加任何說明文字或 markdown 圍欄
