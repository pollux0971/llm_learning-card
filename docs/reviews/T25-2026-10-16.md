## 做法與為什麼

判斷「讀不到」不用 try/catch 包 `loadCardBody`。工單要求縮短版存在但解析失敗要照舊丟錯,catch 寫太寬會把那個錯吞掉。所以在 `io.ts` 只加 `shortCardExists`:跟 `findCardFile` 一樣掃 `cards/` 下一層,用 `existsSync` 看 `<id>.short.md` 在不在,找不到回 false,不丟錯,也不改既有函式。

沒有改 `findCardFile` 去加一個不丟錯的模式,也沒有用「呼叫 `findCardFile` 再抓『找不到卡片檔案』」來判斷缺檔。後者會把判斷綁在錯誤訊息字串上,而且 `readdir` 之類的錯若被當成缺檔,就會誤退回原卡。存在與否跟「檔在但解析壞了」是兩件事,分開查。

`presentNextCard` 的順序:

1. 仍先 `shift` reteachQueue(跟現況一樣,一張卡這次 session 只呈現一次,warning 自然只記一筆)。
2. 縮短版存在 → `loadCardBody(..., { short: true })`,回傳只有 `kind` / `card` / `shortBody`,不帶 `usedOriginal`。解析失敗從這裡丟出去,不記 warning。
3. 縮短版不存在 → `loadCardBody` 讀原卡。原卡也不存在,這個呼叫照舊丟「找不到卡片檔案」,而且發生在記 warning 之前,所以不會留下 `short-card-missing`。
4. 原卡讀到了才記 warning,然後回 `{ kind: 'reteach', card, shortBody, usedOriginal: true }`。`usedOriginal` 的型別是選用字面 `true`,沒有賦成 `undefined`(`exactOptionalPropertyTypes`)。

warning 跟 `session/cache.ts` 的 `warnInvalidSessionCache` 同一條路:`mkdir` 之後 `recordEvent` 寫 `state/log.jsonl`,欄位只有 `ts`、`type: 'warning'`、`card`、`reason: 'short-card-missing'`。`appendLineAtomic` 不建目錄,所以要先 `mkdir`;這一步和寫入包在同一個 try 裡,失敗只吞這一步,不包讀卡。不寫絕對路徑、不寫卡片內容、不補生 `.short.md`。不動 `session.current`、queue、`totalDue`、passed/failed/errors。

終端機只在 `usedOriginal === true` 時把標題接上 `(沒有縮短版,以下是原卡)`,中間不加空白。縮短版存在時那一行的字串與現況相同。

## 待協調

`packages/core/src/session/present-reteach-fallback.test.ts` 的 `writeQuestions`(約第 66–71 行)寫出的題目檔不符合契約,所以下面兩條在退回成功之後、要出第一題時丟 `ZodError`,不是退回邏輯失敗。我沒有改這個測試檔。

- 「退回時 reteachQueue 照常被消耗,其他狀態都不動(session.current、queue、totalDue、passed/failed/errors),下一次照常出第一題」。狀態那些 `expect` 在第二次 `presentNextCard` 之前;失敗堆疊在第 147 行,是 `ZodError`,不是斷言失敗。預期:夾具補成跟 `present.test.ts` 一樣之後,第二次呼叫回 `{ kind: 'question', card: 'sec-0001', progress: { index: 1, total: 1 } }`。
- 「兩張缺縮短版的卡:各退回各的原卡、各記一筆(每卡一筆),之後呈現題目不再多記」。第三次呼叫(註解寫「第一題」)在第 160 行就丟同一個 `ZodError`,後面的 warning 斷言沒跑到。預期:夾具補齊之後,`warningLines` 的 card 仍是 `['sec-0001', 'sec-0002']`(出題不記 warning)。

終端機那支用的 vault 題目檔是合法的,「退回之後照常出題、只記一筆 warning」在那邊是綠的。請測試作者改夾具,不要改實作去吞 schema 錯。
