### 虛擬顯示(Xvfb `:97`)

- `Xvfb :97 -screen 0 1000x700x24 -nolisten tcp -noreset -fbdir <目錄>`,沒有視窗管理員。底色 `xsetroot -solid '#2e8b57'` = (46, 139, 87)。
- 「有合成器」= 再開 `xcompmgr`(預設模式);`_NET_WM_CM_S0` 有擁有者。「沒有合成器」= 不開,擁有者 0x0。
- **截圖讀 Xvfb 的 framebuffer**(`-fbdir` 底下的 `Xvfb_screen0`,本身就是 xwd 格式),不用 `xwd -root`。理由見 O3:有合成器時 `xwd -root` 拿到的是視窗自己的像素(alpha 被丟掉),不是螢幕上合成出來的樣子。沒有合成器時兩者相同。
- 環境上踩到的兩件事(量法,不是 app 的問題):
  - 沒有 `-noreset` 時,最後一個 client 斷線 Xvfb 就重置,`xsetroot` 塗的底色馬上消失(量到全黑)。
  - xcompmgr 不看 `xsetroot -solid` 的底色,只認 root 的 `_XROOTPMAP_ID` / `_XSETROOT_ID`,找不到就塗 128 灰。所以另外放一張同色的 root pixmap 並設這兩個屬性(幾行 Xlib,只准 `:97` / `:98`)。
- XTest 指標動作用一支幾行 C 的小工具(`libXtst`),**只准 `DISPLAY` 是 `:97` 或 `:98`**,對 `:1` 直接拒絕(實測 exit 3)。

## F1:沒有合成器時,視窗出現後第一張是黑的(阻擋項)

### 怎麼量

從 app 啟動那一刻起,每 100 毫秒讀一次 framebuffer,拍 3 秒(31 張)。每一張對兩個視窗(教學 (100, 100, 360, 480)、考試 (520, 100, 360, 480)):

### 原因(gdb 量到的)

- 對 `XMapWindow` 下中斷點:兩個卡片視窗都是 tao 的 `WindowRequest::Visible(true)` → `show_all()` map 的。
- 對 tao 的 `set_visible` 下中斷點:呼叫者是 main.rs 第 99 行的 `on_page_load` 閉包(`PageLoadEvent::Finished`)。
- 對 main.rs 第 95–97 行下中斷點:每個視窗只來一次 `Finished`,網址就是 `tauri://localhost/teach/index.html`、`tauri://localhost/test/index.html`(不是先載入的空白頁)。
- 所以實作照工單做:**載入完才顯示**。黑是因為視窗藏著的時候 WebKit 不畫;視窗 map 之後才畫第一張,這段時間透明視窗(32 位元、alpha 0)在沒有合成器的螢幕上就是黑的。
- **這是工單(我寫的)的設計漏洞**:工單驗收 1 寫「先藏起來,使用者就不會看到先黑再變」,這個假設不成立。開發 worker 沒有做錯。

## 觀察(請顧問判)

- **O1 啟動後哪個視窗拿到鍵盤焦點不固定。** `:1` 兩次開 app:一次教學卡有 `_NET_WM_STATE_FOCUSED`,一次是考試卡。
  T16 之前兩個視窗建好就顯示,後建的考試卡固定拿到焦點;現在是載入完才顯示,後載入完的那個拿到。
  影響:T15 那套步驟裡,作答欄 `focus()` 之後框線要變橘;這次考試卡沒有焦點,`:focus-within` 不成立,框線還是黑的(T15 第四輪是橘的)。改用 CSSOM 複製規則量,長相正確(上表)。
  使用者會遇到的是:開 app 之後直接打字,可能打不進考試卡。要不要固定把焦點給考試卡,請顧問判。
- **O2 Xvfb(沒有視窗管理員)裡,拖曳 / 縮放之後下一次按下會被吃掉。** 兩次:
  - 切角上按住放開(會開始一次縮放)→ 下一次在標題列按下沒有到頁面、視窗也沒動 → 再下一次在內文按下正常。
  - 拖曳完成後 → 切角按下沒到頁面 → 內文按下也沒到 → 第三次才到。
  - 看起來是 GDK 沒有視窗管理員時的模擬拖曳把指標抓著,等下一次按鍵事件才放。真的桌面走視窗管理員的 `_NET_WM_MOVERESIZE`,不同路徑;`:1` 上不能送輸入,所以**沒驗**。只記錄,不當成發現。
- **O3 量法:有合成器時 `xwd -root` 量不到螢幕上真正的樣子。** 對照組:一個 32 位元視窗,左半 alpha 0、右半 50% 紅(預乘)。

  | 讀法 | 左半(alpha 0) | 右半(50% 紅) |
  |---|---|---|
  | `xwd -root` | (0, 0, 0) | (128, 0, 0) |
  | Xvfb framebuffer | (46, 139, 87) = 桌面 | (151, 69, 43);預期 (151, 69.5, 43.5) |

  `xwd -root` 拿到的是視窗自己的像素(丟掉 alpha),所以第一次量有合成器的情況時切角全黑、面板內部 (230, 230, 230)(0.9 白疊在黑上)。
  那一輪作廢,改讀 framebuffer 重拍(上面的數字都是 framebuffer)。工單驗收 11 寫的是 `xwd -root`,之後的工單(T21)量法要改寫。
