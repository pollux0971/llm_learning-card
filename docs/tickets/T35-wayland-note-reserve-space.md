## 為什麼有這張

T34 的提示是 `position: fixed`,疊在捲動區上面,佔掉捲動區最下面 52 px(提示 y 418.8–472,捲動區到 471)。

- 捲到底時,內容最後那段永遠在提示底下。結果畫面的「下一題」、教學卡的「下一個」剛好在最後,於是**整顆看不到**(B4 量到重疊 100%)。
- 擺位程式只看別的按鈕的**正中心**,而且只在 DOM 子節點變動時重擺,捲動不重擺。
- 提示是 `pointer-events: none`,點擊穿過去,所以「正中心點得到」的量法(T15、T34 的 Chrome 測試)永遠過,看不出畫面上的覆蓋。

真畫面(巢狀 Wayland 合成器的 framebuffer)也一樣:兩張卡捲到底,畫面上找不到那兩顆按鈕。使用者桌面是 X11,不受影響;但 Wayland 使用者第一次用會找不到「下一題」。

## 規則(這張要做到的樣子)

1. **提示固定在底部,不往上挪**:左右各 8 px、離視窗底 8 px,跟 T34 第一次擺的位置一樣。捲動、換畫面、縮放都不移動它。T34 的「蓋到按鈕中心就往上挪」「還蓋到就改成右下角窄條」兩段拿掉。
2. **讓出位置**:提示在的時候,主捲動區的 `padding-bottom` 變成「原本的值 + 提示現在的高度」(`getBoundingClientRect().height`)。
   - 主捲動區 = HUD 卡片視窗的捲動區 `[data-hud="panel"].hud-fill .hud-body`(`../../packages/ui-shared/src/hud/hud.css`,原本的 `padding-bottom` 是 1rem = 16 px)。找不到就不加。
   - 這樣捲到底時,最後一樣東西停在提示上緣之上約 17 px(= 16 + 53.2 − 52.2),提示底下只剩空白。
3. **提示的高度變了就重算留白**:視窗變窄或變寬、字型晚到換行改變,都讓提示高度變。留白要跟著改成新的高度。
4. **按「知道了」之後拿掉留白**:捲動區的 `padding-bottom` 回到原本的值(拿掉這張加上的 inline 值,不是寫死 16 px)。
5. 其他照 T34:字樣、按鈕、`localStorage` 鍵、等頁面載入完才畫、X11 不帶這段程式。
   - 樣式只走 CSSOM。顏色只用 `var(--hud-*)`。不用 `style` 屬性、`innerHTML`、`<style>`。
   - 提示盒子保留 `pointer-events: none`、按鈕 `auto`:點擊穿過去,下面的「已知代價」那兩顆,在被蓋住的時候還是按得到。
   - 不改 `hud.css`、HUD 元件、兩張卡的 `App.svelte`。執行時對 `.hud-body` 用 CSSOM 設一個 inline 的 `padding-bottom`,是這張唯一碰到提示以外的元素的地方。

### 跟顧問原裁決的差別(顧問 2026-10-21 同意)

裁決寫「擺位看整個矩形;捲動與縮放時重算」。我把它落實成上面的第 1 條「**不擺位**」,理由:

- 提示往上挪,一定會蓋到別的東西。
  - B4 的應用題結果畫面,T34 把提示挪到 391.8–445:回饋那一行字(391.4–415.4)整行被蓋,「下一題」還是 39% 在下面。
  - 看整個矩形的話,要挪到 370.2–423.4 才讓開「下一題」,一樣蓋掉那行回饋。
  - 四行題幹那題要讓開「送出」,得挪到 334.2–387.4,會蓋到作答框(到 382.4)。
- 有了第 2 條的留白,每一顆按鈕都捲得出來,不需要靠挪。
- 捲動時重擺會讓提示跟著捲動跳上跳下。

所以改壞證明的第 3 種,從「捲動時不重擺」改成「**提示變高時不重算留白**」(must_catch 第 3 條)。第 2 種「改回只看正中心」照舊:把 T34 的往上挪加回去,要紅。

## 驗收條件

### 1. 自動測試(真 Chrome,測試 agent 寫;開發 worker 不改)

照 `../../packages/ui-shared/src/hud/card-render-wayland-note.test.ts` 的做法,載入「Rust 交給頁面的那段程式」。

| 量什麼 | 過的條件 |
|---|---|
| 提示在底部不動 | 第一次出現、換到下一個畫面、捲到底、捲回頂,提示的矩形都一樣:左右 8、離底 8 |
| 留白 | 提示在的時候,`.hud-body` 的 `padding-bottom` = 原本的值 + 提示的高度(±0.5 px) |
| 捲到底不蓋 | 考試卡至少一個「下一題」在一屏外的結果畫面、教學卡:捲到底之後,每顆按鈕與每個輸入框跟提示的**矩形重疊面積都是 0**,提示底下沒有有字的元素 |
| 變窄重算 | 視窗寬度改到讓提示明顯變高(例如提示多一行以上;按鈕被擠到第二行也算),等一下:留白等於新的高度,捲到底仍然重疊 0 |
| 按掉 | 按「知道了」:提示不見,`padding-bottom` 回到原本的值,沒有 inline 的 `padding-bottom` |
| X11 | 沒有提示,`padding-bottom` 是原本的值 |
| 不退步 | T34 的提示測試全綠 |

- **「有沒有蓋住」一律用矩形重疊量**,不准只用 `elementFromPoint`(提示是 `pointer-events: none`,會穿過去;這次的盲點就是這個)。`elementFromPoint` 可以另外量「點得到」,不能當「沒蓋住」的證據。
- Chrome 測試的視窗大小跟真 app 不一定一樣,所以這裡量**規則**(不動、等高、重疊 0、重算、拿掉),不比上面那張表的數字。表的數字由 `@manual` 量。
- 靜態檢查照 T34:提示程式沒有 `style=`、`innerHTML` 帶樣式、`<style>`、色碼字面值。

## 做法建議(不綁做法,量的結果才是驗收)

- 用 `ResizeObserver` 看提示自己的大小:寬度、字型、換行讓高度變了,它都會叫,在那裡重設留白。
- 設 `padding-bottom` 前先記下 `.hud-body` 原本的 inline 值(通常是空的)與計算值。按掉時把 inline 值還原,不要寫死 16 px。
- T34 的 `MutationObserver` 只為了擺位;不擺位之後可以拿掉,或只留著確認 `.hud-body` 還是同一個元素(換畫面時 Svelte 不會換掉它,但留著不貴)。
- 改 `.hud-body` 的 inline style 不會觸發 `childList`,不會跟 `MutationObserver` 互相叫來叫去。
