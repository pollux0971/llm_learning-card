# 平行與整合策略

這份文件解釋 roadmap 為什麼長那樣。讀完你就知道每個 phase 的順序不是隨便排的。

## 兩個要求,一個答案

你的兩個要求看起來矛盾:

- 一開始所有資料夾的第一階段要能**完全平行**
- 每次整合都要是**完整可用的系統**

平行意味著彼此不知道對方存在;可用意味著彼此要接得起來。答案是把「接口」和「實作」分開:
**接口先凍結(contracts/),實作各自平行,整合只是把 stub 換成真的。**

## 為什麼 Wave 0 真的能平行

Wave 0 是十個資料夾的 phase-1 同時開工。能平行的三個條件:

**一、契約已凍結。** `contracts/types.md` 定義了所有跨模組的型別與檔案格式。
沒有人需要等別人決定「Review 長什麼樣」。

**二、每個功能只依賴 contracts,不依賴彼此。**
需要別人的能力時,用 contract 定義的介面 + 自己的假實作:

| 功能 | 需要什麼 | Wave 0 怎麼辦 |
|---|---|---|
| 02-ingest | LLM | `FakeLlmRouter` 重播 `fixtures/llm/` |
| 05-grading | LLM | 同上 |
| 06-test-card | 排程、審核、檔案 | 三個 stub + `MemoryFs` 吃 fixture |
| 07-teach-card | 卡片、order、檔案 | `MemoryFs` 吃 `fixtures/learning-rich` |
| 09-lint | 驗證器 | 自己寫最小版,I6 換成 data-layer 的 |
| 10-desktop-shell | 內容 | 兩個 placeholder HTML |

**三、共用 fixture。** `contracts/fixtures/` 是**真的檔案**,不是規範——三張真的資安卡、
三份考題、一份原始素材、預錄的模型回應、刻意壞掉的目錄。每個功能第一天就有東西可以吃,
不必自己造假資料。整合時大家對「sec-0001 是什麼」的理解一致。

**一個例外:組合層。** `11-review-cli` 的工作就是把 scheduler、grading、檔案讀寫串起來。
它在被串的東西存在之前無法獨立,硬造一個吃 stub 的版本等於寫兩次。所以它不參與 Wave 0,
phase-1 直接在 I2(ADR-028)。**遇到類似的情況比照辦理**:在 FEATURE.md 說明理由、
記一筆 ADR,不要為了湊規則而製造重工。

## 代價:短暫的重複

Wave 0 期間會有幾份重複的東西——每個需要 LLM 的功能都有自己的 `FakeLlmRouter`,
09-lint 有自己的最小驗證器。這是**刻意的**:

> 一點重複,遠比一個依賴鏈便宜。

依賴鏈的成本是「A 沒做完 B 就不能開始」;重複的成本是整合時刪掉幾十行。後者便宜太多。

`/phase-acceptance` 會列出這些重複,整合時逐一移除。

**其中一份重複意外地有價值**:09-lint 在 Wave 0 有自己的最小驗證器。
它跟 01 的驗證器對 `contracts/fixtures/cards/wordcount-cases.md` 如果算出不同的字數,
那就抓到了契約的歧義。這種檢查**只有在有兩份獨立實作時才做得到**,錯過就沒了。
(v1.0 的契約就有這樣一個歧義:`same-origin` 到底算 1 還是 2。v1.1 補上了明確定義。)

## 為什麼每次整合都是完整系統

不做「整合到一半」。每個 integration 的驗收條件都是一句**使用者做得到的事**:

| 整合 | 你做得到什麼 |
|---|---|
| I1 | 丟一篇文章進去,得到一疊可讀的卡片 |
| I2 | **每天在終端機複習,間隔重複真的在跑** |
| I3 | 在桌面視窗裡複習,不用終端機 |
| I4 | 兩張卡完整運作,不用開 Obsidian |
| I5 | 開機就在,週目標會計數 |
| I6 | 離線用完再補審,壞掉的卡查得出來 |
| I7 / I8 | macOS / Windows |

**I2 是關鍵**:那時系統就已經有價值了。之後每一個整合都是讓它更好用,不是讓它「終於能用」。
這代表如果專案在任何一個整合點停下來,你手上都有一個能用的東西。

## 每個資料夾的功能單獨可跑

不只 Wave 0。每個資料夾的 `FEATURE.md` 都有「單獨執行」段落,寫著一行可以複製貼上的指令。
整合之後這些指令**仍然要能動**——這是刻意的約束,它強迫模組保持鬆耦合。

`/phase-done` 會實際跑一次那個指令。跑不起來就不算 done。

## 誰決定下一步

每個資料夾有 `NEXT.md`,寫著:

- 目前在哪個 phase
- 下一個 phase 的 gate(要滿足什麼才能開始)
- gate 沒滿足的話,現在該做什麼

Gate 有三種:

| 種類 | 意思 | 例 |
|---|---|---|
| 自身 gate | 本資料夾前一個 phase 要 done | phase-2 需要 phase-1 done |
| 整合 gate | 某個 integration 要通過 | phase-2 需要 I1 通過 |
| 契約 gate | 某個待決事項要決定 | phase-2 需要決定本機模型 |

`/sprint-planning` 讀所有 `NEXT.md` 決定哪些 phase 是 ready。
建議讓指令維護狀態,這樣 gate 計算才準;手動改也不會壞,只是建議會失準。

## 整合的順序不能改

Wave 0 的十個可以任意順序、任意平行。
I1 到 I8 **必須依序**。因為每個整合都建立在前一個之上,而且每個都要求「系統是完整可用的」——
跳過 I2 直接做 I3,就會得到一個有 UI 但排程沒驗證過的東西,那不是完整可用。
