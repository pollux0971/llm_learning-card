## 量法

### 每一幀的按鈕位置

教學卡頁面裡裝一支小程式,在**每一個畫面幀**(`requestAnimationFrame`)與**每一次 DOM 變動**(`MutationObserver`)都記一筆:

- 每顆按鈕的 `getBoundingClientRect`(`.hud-body` 裡所有按鈕,不含生成中那一行裡的「取消」),到小數第 2 位;
- `.hud-body` 的 `scrollTop`、`scrollHeight`、`clientHeight`;
- 留的位置(`.status-slot`)的高度;
- 現在是哪種字樣、卡片標題。

跟上一筆一樣就不記(去重)。量一次轉換:記下按之前最後一筆 → 真的指標按 → 等畫面安靜下來(`teach.deepen` 有回應、最後一個請求之後 1.5 秒沒有新的、按鈕回到可以按)→ 拿這段時間同一張卡的每一筆,跟按之前那一筆比。表裡的「差」是這段時間裡**任何一幀**、任何一顆按鈕、x / y / 寬 / 高四個數字裡最大的差。

這支程式在整段量測都在跑。量每一次轉換的時候,它已經跑過 132–3164 個畫面幀(看那次開 app 多久了);它是每一幀都看,只是沒變的不記,所以不是只有前後兩個點。

### 短卡、長卡

- **短卡**:內容放得下、不用捲(`scrollHeight` = `clientHeight` = 433 px)。
- **長卡**:暫存根裡把沒有子卡那張與 level 4 那張的內文後面加一個長的例子區塊(例子不算 100 字),各開一次 app。沒有子卡那張 `scrollHeight` 1209 px、可以捲 776 px;level 4 那張 1251 px、可以捲 818 px(工單要 ≥ 150 px)。量之前把 `.hud-body` 捲到底(`scrollTop` = `scrollHeight - clientHeight`,量過到底了)。捲動這一步是量測程式做的,轉換本身都是真的指標按。

### 每種字樣怎麼做出來

都是真的側車回的,不是注入:

| 字樣 | 怎麼做出來 | 真 app 的順序 |
|---|---|---|
| 生成中 | 在線,每個模型呼叫延遲 4 秒 | 按深入 → 生成中 |
| 其他深入錯誤 | 子卡的回應不是 JSON | 按深入 → 生成中 → 輪詢拿到 `deepen-failed` |
| 沒有模型 | 雲端、閘道都連不上 | 按深入 → 生成中 → 輪詢拿到 `no-model` |
| 金鑰被拒絕 | 子卡那個呼叫回 401(這次新加的假網路模式) | 按深入 → 生成中 → 輪詢拿到 `credential-unavailable`,字是 rejected / `OPENAI_API_KEY` 那句 |
| 金鑰沒有設定(最高那句) | `.env` 選雲端 anthropic、不放 `ANTHROPIC_API_KEY` | 按深入 → `teach.deepen` 直接回 `credential-unavailable`,字是 missing / `ANTHROPIC_API_KEY` 那句 |
| 最深一層 | level 4 那張 | 按深入 → `teach.deepen` 直接回 `deepen-floor` |

- 每種都量過畫面上的字就是 core 的那一句(`credentialMessage(…, 'deepen')` 與 `ERROR_MESSAGES` 從簽出直接讀出來比,不手抄)。
- 真的 app 裡,「沒有模型」「其他深入錯誤」一定先經過生成中,沒有「沒字 → 直接出這兩種」的路;所以這兩種量的是「沒字 → 生成中 → 錯誤」,一段裡兩次轉換都量到。

### 量法看得到紅(故意改壞)

為了確定上面那些 0 不是「量法看不到」,另外開 2 次 app,用 CSSOM 在暫存的 app 裡把畫面改回壞的樣子(只改那次開著的頁面,不改原始碼),做同樣的轉換:

## 留的位置有多高(協調者要的:67.4 px 那個數字)
