```json

  "beforeDevCommand": { "script": "npm run build:frontends", "wait": true },
```

- apps/desktop/package.json 的 `build:frontends`:
  `vite build ../teach-card --base /teach/ --outDir ../desktop/dist/teach --emptyOutDir && vite build ../test-card --base /test/ --outDir ../desktop/dist/test --emptyOutDir`。
  teach-card、test-card 的檔一個都沒改(落點只動 apps/desktop/)。`dist/` 已在根 .gitignore。
- 兩個視窗 `url`:`teach/index.html`、`test/index.html`。建出來的 html 引用 `/teach/assets/index-*.js`、`.css`,
  靜態檢查通過;bundle 裡沒有 `eval` / `new Function` / `style=`(只有 Svelte 的 `innerHTML` 模板)。
- **沒有設 `devUrl`,開發模式用「等效設定」**:`beforeDevCommand` 先建好前端(`wait: true`),`tauri dev` 吃的是
  跟正式版同一份 `frontendDist`。理由:(1) 兩個前端是兩個 Vite 專案,沒有一個 dev server 能同時服務兩個視窗;
  (2) Tauri 2.11.5 只有對內嵌的資產注入 CSP,用 `devUrl` 的話開發模式根本沒有 CSP,F19 的「console 沒有 CSP 違規」
  就看不到東西。代價:桌面殼裡沒有 HMR(各前端自己 `npm run dev` 在瀏覽器裡照樣有)。**因此不需要 `devCsp`。**
- 沒有 `devUrl` 時,`cargo build` / `cargo test`(不經 tauri CLI)在 `../dist` 不存在時會被 `generate_context!` panic
  (tauri-codegen 2.6.3 context.rs:「The `frontendDist` configuration is set to … but this path doesn't exist」)。
  build.rs 先 `create_dir_all("../dist")`,所以乾淨簽出直接 `cargo test` 也編得過(那樣編出來的視窗是空白)。

**csp 最後的字串**:

```
default-src 'self'; script-src 'self'; object-src 'none'; frame-src 'none'; img-src 'self' lc: data:; connect-src ipc: http://ipc.localhost
```

- 工單的五個指令照抄;`script-src` 沒有 `unsafe-inline` / `unsafe-eval`。
- **IPC 來源是我自己加的:`connect-src ipc: http://ipc.localhost`**。讀 tauri 2.11.5 原始碼(manager/mod.rs 的 `set_csp`)
  確認 Tauri **只**往 `script-src`、`style-src` 補 nonce 與 hash,**不會**自己往 `connect-src` 加 IPC 來源
  (工單 E13 說「Tauri 2 會自己往 CSP 加 IPC 需要的來源」,這一點與原始碼不符,回報)。
  `ipc:` 是 Linux/macOS 的自訂協定,`http://ipc.localhost` 是 Windows 的形式。
- **「設了 csp 之後 invoke 是否照常能用」:沒有實測**(這張不准開 GUI)。依據原始碼:IPC 用 `fetch('ipc://localhost/…')`,
  被 CSP 擋掉時 `@tauri-apps/api` 會退回 postMessage;加了 `connect-src` 之後走的是正常路徑。要由 F19 的 @manual 確認。
- `img-src` 沒有加 Windows 的 `http://lc.localhost`(phase-5,見已知限制)。
