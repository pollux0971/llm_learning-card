## 做了什麼

- `scripts/check-gates-pinned.sh`:本 repo 自己的包裝腳本,第一行是 `#!/usr/bin/env bash`,不是 `SOURCE` 標頭。
- `package.json` 的 `check:gates` 改呼叫它:`bash scripts/check-gates-pinned.sh`。
- 測試先 commit(`00c6912`,當時 6 支全紅),再寫腳本讓它們轉綠。轉綠之後沒有改測試。

釘版本的路徑(沒設 `TEMPLATE_DIR`):

1. 掃 `scripts/` 底下每個檔的**第一行**(`head -n 1`;要比對時 `grep -a`)。符合 `^(//|#) SOURCE: template v` 的才算。
2. `(版本, commit)` 必須恰好一種。零種或多於一種都紅,列出檔名與值,不准多數決。
3. 標頭 sha 必須在 `TEMPLATE_REPO` 裡**本身就是 commit**(不先剝 `^{commit}`,否則 annotated tag 的物件 sha 會被當成合法 commit)。
4. `git rev-parse "${version}^{commit}"` 必須等於那個 commit。比的是 commit,不是 tag 物件。
5. `git archive` 那個 commit,確認解得出 `scripts/sync-gates.sh`,再跑 `--check`。暫存目錄 `trap` 清掉。`set -euo pipefail`。
6. repo 不存在、commit 不存在、archive 失敗、解不出 `sync-gates.sh`,都紅,沒有退回活 HEAD 的分支。

## 拿掉檢查,哪個測試會變紅

審核者做實際對照。下面是預測,不是我跑過的變異。

| 拿掉的檢查 | 會變紅的測試 | 為什麼 |
|---|---|---|
| repo 存在(`[ ! -d "$repo" ]` 那段) | `不存在的 repo:非零,且不准退回預設路徑` | 剩下的是 git 的 `cannot change to`,不含 `✗ 模板 repo 不存在:`。若改退回預設路徑,也不會印這句。 |
| commit 存在(`cat-file -t`,不存在就印 `✗ commit 不存在於模板 repo:`) | `不存在的 commit:非零,且不准退回活的 HEAD` | 測試斷言那句,以及 stub 沒被叫到。退回 HEAD 會叫到 stub、rc=0。改走 `git archive` 失敗的話,fatal 也不含那句。 |
| 恰好一種、不准多數決(`n_combos -ne 1` 那段) | `混版標頭:...不准多數決` | 拿掉之後會讀到第一組(`v1.0.0` / commit A),tag 對得上,archive 的 stub 以 0 結束。兩個 commit 都存在,所以變紅的不是「commit 不存在」。 |
| 明設時印 `TEMPLATE_DIR 明設,未驗證釘版本` | `直接用明設目錄,...` | `toContain` 那一行。 |
| 明設時直接執行、不走 archive | 同一支 | `TEMPLATE_REPO` 不存在且標頭混版;改走釘版本就不會是 rc=0,也看不到 `DIRECT_TEMPLATE_DIR`。 |
| `^{commit}`(改拿 `git rev-parse "$version"` 的 tag 物件來比) | `annotated tag 的物件 sha 不同於 commit 時,標頭寫短 commit 仍綠` | tag 物件 ≠ 短 commit 展開後的 commit,比對失敗,rc≠0。 |
| 「型別必須是 commit」整段,直接 archive 標頭 sha | `標頭寫 annotated tag 的物件 sha 時必須紅` | `git archive <tag 物件 sha>` 實測 rc=0,stub 會被叫到,且沒有 `不是 tag 物件` 那句。 |
| `head -1`,改掃全檔 | 混版那支,以及驗收 5 正向那支 | 混版 fixture 的 `scripts/local.ts` 正文有 `v3.0.0`,輸出不准出現。正向 fixture 的 `scripts/trap.ts` 正文有另一組標頭,掃進去就不是恰好一種。 |

`grep -a` 沒有單獨的測試:正確寫法是先 `head -1` 再 grep 那一行,那一行不是二進位,`-a` 拿掉也不會漏檔。實作仍加了 `-a`,符合工單。正常路徑的 25 之中有 `check-known-defects.ts`,證明第一行掃描沒有把它丟掉。
