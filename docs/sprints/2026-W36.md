## 本週學到、值得記住的

- **phase 全部 done 不等於整合完成。** `/integrate` 的重複清除檢查抓到 I1 有兩個真的「接線」缺口,個別 phase 的驗收都不會發現這種東西。以後整合點的 gate 一滿足,第一件事就該是開一張獨立的「整合工作」工單,內容照抄 roadmap 該整合點的「整合工作」欄 + 各 `FEATURE.md` 的「Wave 0 的重複」表——不能假設它會在某個 phase 裡順便發生。
- **審核不能只信「等價變異」的口頭判斷。** 兩次退回都是這個原因(01/phase-3、11/phase-1 更是直接抓到一個會讓程式當掉的真 bug)。存活變異一定要照四分類(真漏測/真等價+精確理由/死程式/邊界)逐條處理,「等價」是要能寫進 `// Stryker disable next-line all: <理由>` 的東西,不是一句話帶過。
- **同一個概念的兩個 ctx,一個是陣列一個是單值,幾乎一定是漏了一條路徑。** `FailCtx.answers[]` vs 舊版 `PassCtx.type/grader` 對稱破掉,正是 stage-2「兩題都對」這條最常見的成功路徑完全沒場景覆蓋、實際上會讓程式當掉的根因。以後審核多一句嗅覺檢查。
- **cucumber tag 的「屬於」與「保護」不要用同一個 tag 表達。** `@regression @i1` 這種寫法在 `not @i1` 篩選時會被連坐排除。改成 `@regression` + 場景名寫清楚保護對象(`… still works as in I1`),i2–i8 的骨架場景已經統一改過。
- **worktree 從舊 commit 分支的老問題**:`orca-ide worker-start --worktree new-top-level` 沒帶 `--base-branch` 有機率抓到 stale base。這次三次踩到都是用 `--base-branch main` 明確指定起點解決,之後預設都帶這個參數。

### 今天學到的(形狀,不是個案)

1. **修實例會被慣例重新產生,只有修慣例才停得下來。** 早上把根目錄那份佔著交接路徑的 `REVIEW.md` 搬走;**同一天下午陷阱長回來了**,因為下一條分支照 P-17 的慣例又在那裡寫了一份。正解是把慣例路徑改到一個本來就 gitignore 的目錄(模板 1.4.2 做了)。
2. **同一個警告寫第三次,就該改結構。** 那份 `REVIEW.md` 被兩份文件寫過「別覆蓋」,第三個人還是覆蓋了。
3. **「這句話是怎麼來的」比「有幾個人同意」重要。** 今天四次「有人把推論當事實」,其中兩次是我、一次是技術顧問、一次是兩人一致。**第四次第一次在寫進檔案之前就被攔下來。**
4. **`ok` 證明的是「我的動作成功」,還是「對方真的收到了」?** 會話中途唯一可靠的訊號是 **`git log` / `git status` 有沒有動** —— 那是唯一不經過那個可能壞掉的工具層的訊號。(我自己踩過:兩種送法都回 `ok`、token 不動,判定「沒收到」,**實際上收到了**。)
5. **「提示」比「FAIL」危險** —— FAIL 擋住你,**提示誘導你去改基準**。
6. **當量尺的「好」方向剛好是「資料變少」的方向,資料遺失與進步不可區分。**(來源:nightmare-assault)
7. **cmdline 是「宣稱」,`ran/collected` 是「驗證」。鎖只需要宣稱(多鎖一次只是多等);指標需要驗證。**(來源:nightmare-assault)
8. **安全的錯誤方向要從「錯了會怎樣」重新推一次,不能繼承。**「我搬了你的結論,沒搬你的前提。」(來源:nightmare-assault 的工人,對象是**我給的規則**)
9. **新東西不准用舊債的身分進來。** 零輸入守門的基準只收「守門誕生前就存在」的洞。今天這條擋下兩個當天才進來的洞。
10. **不對自己開例外的價值**:「不准繞過鎖」那條掃描器今天抓到三次,**三次都是「自己人」** —— 模板的測試資料、模板的設定檔、worker 自己的交接筆記。
