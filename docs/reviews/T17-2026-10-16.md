## 做法與為什麼

快取放 `${XDG_CACHE_HOME:-$HOME/.cache}/llm-learning-cards/<vault_id>/session-<YYYY-MM-DD>.json`。`XDG_CACHE_HOME` 與 `HOME` 空字串都視同未設。vault-id 用既有的 `parseMarker`(容許一個結尾換行、必須是 uuid);沒有或格式不對就用 `path-` 加 `--dir` 真實路徑 sha256 前 16 個十六進位字元。寫入只走 `writeFileAtomic`,寫完刪掉同一個帳本資料夾裡其他日期的 `session-*.json`,不動別的帳本。壞掉(讀不到、不是 JSON、schema 不過)丟掉重建,並在 state/log.jsonl 記一筆 `warning`,`reason` 是 `session-cache-invalid`,`path` 只寫檔名。`date` 不等於今天算過期,重建但不記 warning。

題目集合與順序用快取的 queue,不再呼叫 `selectSession`。已答只看 reviews.json 裡 `date === today` 的 history;答過的從記憶體 queue 拿掉,`totalDue` 維持快取分母,所以續答第一題是 3/5 不是 1/3。題型與 stuck 以 reviews.json 的 stage 為準(快取不存答案;手寫快取的 stage 可能跟帳本不一致,紅測試的 stage 3 應用題就是這樣)。帳本沒有這張卡或 stage 不在 1–5,才退回快取的 stage。

小結的 passed / returned / retryLater 從快取名單加 reviews.json 算,不從本次計數器抄。一張卡通過 = 今天每一筆有效結果(`revised_to ?? pass`)都通過。沒有今天 history 的卡是 retryLater,K 為 0 不印。明日預估的回退數用同一個 R。`Answered this run` 只在當日快取於這次執行之前就存在時才傳進 `renderSummary`(含 0);一次跑完不傳,小結跟 phase-1 位元組相同。舊呼叫端不傳 `retryLater` 時仍印舊的 grading-error 行,CLI 一律傳 `retryLater`,所以那行被取代。

檢查順序:用法錯誤(含 `--pause` 與 `--unpause` 同時)→ 0 張卡 → `--pause` / `--dry-run` 結束、`--unpause` 只關暫停 → 快取標記暫停則在查帳本之前擋下 → 互動才查帳本 → 讀或建快取 → 答題 → 小結 → 本次作答至少 1 題才 `snapshotLearningDir`。snapshot 失敗印 hint 或 `snapshot 失敗:` 加原因,不改退出碼、不印 stack。not-a-repo 用既有的 `NOT_A_REPO_HINT`(含 `cli.ts init` 與版本控制)。`--dry-run` 有合法今日快取就列剩下的題、標題 `已答 X / 共 N`,不寫檔;壞快取不重建、不寫 warning,改現算並說明快取無法讀取。

stdin 關掉時 readline 的 `question()` 會掛著(實測 /dev/null 會 TIMEOUT),所以在 `close` 時 abort,當成使用者離開,已落地的答案保留,小結照印,0 題不 snapshot。
