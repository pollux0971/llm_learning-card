## 4. 選的做法,以及為什麼

- **`surface_for` 只看 `mode.solid`。** 有合成器(`solid == false`)回 `transparent: true`、`background: None`;沒有合成器回 `transparent: false`、`background: Some(SOLID_BACKGROUND)`。不另外問 GDK、不開視窗,單元測試才測得到。工單的表就是這兩列。
- **色值是 hud.css 的副本,不 `include_str!`。** `--hud-solid` 現在是 `#f4f6f8`,所以 `SOLID_BACKGROUND = [0xf4, 0xf6, 0xf8, 0xff]`。alpha 255 是不透明。工單不要桌面殼的建置綁到 `packages/ui-shared` 的檔案位置;T16 的 class 名字也是「Rust 一份、測試讀真的檔比對」,這張照同一個做法。`hud.css` 沒改。
- **設定檔拿掉 `transparent` 鍵,不是改成 false。** 透明只由程式決定。teach 與 test 的 `decorations: false`、`visible: false`、`create: false`、大小位置都不變。
- **建窗時套,不在 `.build()` 之後補。** `open_windows` 仍只呼叫一次 `desktop_is_composited()`,算出的 `mode` 同時給 `init_script(mode)` 與 `surface_for(mode)`。卡片 builder 先 `.transparent(surface.transparent)`(參數是欄位,不是字面 true/false),`surface.background` 是 `Some` 才 `.background_color(tauri::window::Color(...))`,然後才 `.build()`。建好之後才改,第一張可能已經畫錯,所以不用 `set_background_color`。setup 視窗(`start_screen::WINDOW_LABEL`)的建立鏈沒動。置頂、`initialization_script`、`on_page_load`、3 秒退路、window-state 的 `StateFlags` 都沒動。
- **`StartupFocus` 記還沒顯示的標籤,只給一次。** `new` 時若 labels 裡沒有 `STARTUP_FOCUS`(`"test"`),pending 留空,之後永遠 `None`(四種失敗、只有教學卡)。有的話把標籤去重放進 `Vec`(兩個標籤,不必上 HashSet)。`on_shown` 不在集合裡、或同一個標籤第二次,都不算。pending 清空的那一次回 `Some(STARTUP_FOCUS)`,並把 `given` 設上,之後都 `None`。先 teach 再 test、先 test 再 teach,都是第二次才回 `"test"`:教學卡後顯示搶走焦點時,回的仍是考試卡,不是剛顯示的那個。
- **`set_focus` 放在一個 helper,兩個顯示處都呼叫它。** 工單要 Finished 與 3 秒退路在 `show()` 之後都通知,而且 `set_focus` 全檔只一處、只在 `on_shown` 回 `Some` 時、對 `get_webview_window(回傳的標籤)`。兩處各寫一次 `set_focus` 會讓靜態檢查紅,所以 `focus_if_both_shown` 負責 `on_shown` 與那唯一的 `set_focus`;`on_page_load` 的 Finished 與 `arm_show_fallback` 的逾時都在 `show()` 之後呼叫它,參數是這個視窗自己的標籤,不是字面 `"test"`。`StartupFocus` 在迴圈之前用 `start_screen::windows(state)` 建一個,放進 `Arc<Mutex<…>>` 給每個視窗共用。頁面卡住、靠 3 秒退路才顯示的那一次,焦點也是兩個都顯示之後才給。
