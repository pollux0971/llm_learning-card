### D1 的量法(工單驗收 8)

指令(Chrome;WebKitGTK 是同一套步驟換成檢查器跑,再用 `headcontrast.py` 對截圖算):

```bash
npx tsx t15/cdp-gallery.mts 9333 http://127.0.0.1:5199/ t15/dev
```

每一個背景(不勾、勾深色、對照組)做三件事:

1. 找頁首 `[data-gallery="head"]` 裡「自己直接有文字」的元素(有非空白的文字子節點),記下它的計算字色與矩形。
2. 插一條規則把頁首的字設成透明、checkbox 設成 `visibility: hidden`,截整頁。這張就是「字背後的像素」。
3. 對每個元素:字色對它矩形裡**每一個**像素算 WCAG 對比,取最小值。

核心(照抄 `cdp-gallery.mts`):

```ts
const lin = (c: number) => { const s = c / 255; return s <= 0.03928 ? s / 12.92 : ((s + 0.055) / 1.055) ** 2.4; };
const lum = ([r, g, b]) => 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b);
const contrast = (a, b) => { const [x, y] = [lum(a), lum(b)].sort((p, q) => q - p); return (x + 0.05) / (y + 0.05); };
// 對元素矩形裡的每個 (x, y):worst = min(worst, contrast(字色, px(字設透明後的截圖, x, y)))
```

對照組:勾著深色背景,再插一條 `[data-gallery="head"] { background: transparent !important; }`(只在 headless 頁面上,不改檔),用同一個量法。

## 觀察(請技術顧問判,前端不判)

### O1:作答欄裡面是灰色,不是面板的白

- 展示頁量到:作答欄內底 (230, 230, 230);面板內部 (251, 252, 253)。兩個引擎一樣。
- 原因:作答欄跟 HudButton 用同一種畫法(黑底 + 1 像素內距 + 裡面墊 `--hud-panel`)。`--hud-panel` 不透明度 0.9,疊在黑底上就是 0.9 × 255 ≈ 230。
  按鈕現在也是 (230, 230, 230)(展示頁第一顆按鈕的標籤內量的)。
- 看起來的效果:灰底的輸入框,有一點像「停用」。有焦點時變淡橘,所以「能不能打字」還分得出來。
- 要改的話:跟 T14 修面板的方法一樣,黑線只畫成一圈(evenodd 挖空中間),不整片墊在底下。

### O2:多行作答欄右下角有瀏覽器自己的縮放把手

- `textarea` 預設可以拖曳改大小,右下角會畫兩三條斜線,剛好壓在作答欄右下切角的那條細線上(`g-03-fields.png`)。
- 考試視窗的應用題也看得到(`test-03-after-one.png` 右下角)。
- 要改的話:`resize: none`,或只准上下拉(`resize: vertical`)。

### O3:「送出」緊貼作答欄

- 三種情況量到的間距都是 0:單行作答欄底 133.7、送出頂 133.7;多行 268.0 / 268.0;三格填空 251.3 / 251.2。
- 看起來的效果:按鈕的上框線跟作答欄的下框線疊在一起,有點擠(`test-01-first.png`、`test-03-after-one.png`)。
- 工單沒有規定間距,所以這條不算違反。要改的話:送出鍵上面留一點空(例如 0.5rem,跟填空格之間的間距一樣)。

### O4:例子框左邊是 3 像素的黑條

- 工單准許 `.lc-example` 用 `border-left`(顏色只能用 `var(--hud-*)`),實作用了 `3px solid var(--hud-line)`。
- 那是畫面上最粗的黑線;其他的框線都是 1 像素。不算違反,只是跟「很細的黑線」的風格比較不一樣。請顧問看要不要改成 1 像素或拿掉。
