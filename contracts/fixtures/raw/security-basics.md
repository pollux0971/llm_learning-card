# 瀏覽器安全的三個基礎

## 同源政策

瀏覽器不允許一個網頁的程式碼隨意讀取另一個來源的資料。這裡的「來源」由三個部分
組成:協定、主機、埠號。三者完全相同才算同源。

這條規則存在是因為瀏覽器會自動帶上你的 cookie。沒有這條限制,任何網站都可以在背
景向你的銀行發請求並讀到回應內容。

同一主機底下的不同路徑是同源的;把 https 換成 http 就不同源;換一個埠號同樣不同
源,即使主機一樣。

## 跨來源資源共享

同源政策擋得徹底,但實際系統常常需要跨來源。前端在一個網域、API 在另一個網域是很
常見的架構。

解法是讓伺服器明確表態。伺服器在回應裡加上標頭,說明哪些來源可以讀這個回應。瀏覽
器看到標頭符合才把結果交給網頁,否則即使請求成功也讀不到內容。

關鍵在於決定權在伺服器,不在發請求的網頁。網頁不能自己宣稱有權限。

如果請求需要帶上憑證,規則更嚴格——伺服器必須明確指名允許的來源,不能用萬用字元。

## 預檢請求

有些跨來源請求瀏覽器不敢直接送。改變伺服器狀態的方法、或帶了自訂標頭的請求,瀏覽
器會先發一個詢問請求,問伺服器願不願意接受。

伺服器同意之後,瀏覽器才送出真正的請求。這個機制是為了保護那些在同源政策出現之前
就存在的舊系統——它們沒有預期會收到跨來源的寫入請求。

預檢的結果可以被快取一段時間,避免每次都多一趟往返。
